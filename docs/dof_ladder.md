# 자유도 사다리 실험 — 판정 기준 사전 등록

2026-10-30. **천장(S³·S4) 수치를 보기 전에** 쓴 문서다. 아래 '예측'과 '판정 기준'은
결과를 보고 고치지 않는다. 틀리면 틀렸다고 적고 그대로 둔다 (이 저장소의 관례 —
`experiment_plan.md`, `verification.md` 2026-09-28 절).

---

## 0. 왜 이 실험인가

이 연구에 대한 근본적 비판: 최근 곡면 레이어 연구(S³-Slicer 2022, CurviSlicer 2019,
Neural Slicer 2024)는 레이어 형상을 **임의의 변형장**으로 푸는데, 우리는 그것을
축대칭 원뿔에 높이의 함수 θ(z) 하나로 **묶었다.** 자유도를 줄인 것이다.

그 제한의 **대가가 서포트에서 얼마인지**를 같은 모델·같은 자로 재는 것이 이 실험이다.
자유도를 0(평면)부터 연속(S³)까지 사다리로 놓고, 칸마다 남은 서포트 % 를 찍는다.
결과가 어느 쪽이든 쓸모가 있다:

* 격차가 작은 모델 부류가 있으면 → "그 부류에서는 경량으로 충분" 이 수치로 선다
* 격차가 크면 → 적용 범위 판별기의 문턱과 **다음 자유도 칸의 우선순위**가 데이터에서 나온다

⚠ 이 실험은 **서포트 축 하나**만 본다. 저자유도의 이득(닫힌 식 보장, 회전축 요구량
유계, 외부 슬라이서 호환, 반증 가능성)은 이 표에 **안 나온다.** 그것은 둘째 축
(§6)과 별도 논의의 몫이다. 여기서는 **지는 쪽을 정직하게 재는 것**이 목적이다.

## 1. 사다리의 칸

| 칸 | 자유도 | 구현 | 상태 |
|---|---|---|---|
| 평면 | 0 | θ = 0 | 있음 |
| 균일 원뿔 (서포트 최소) | 1 | 0~44° 2° 격자 전수, outward | 있음 |
| 균일 원뿔 (J 선택) | 1 | `select_uniform`, k=0.2 | 있음 (실제 파이프라인이 고르는 값) |
| θ(z) 밴드 N=2, 3, 4 (J 선택) | N | `select_banded_j`, k=0.2, k_blend=0.1, 층간격 상한 1.5 | 있음 |
| + 축 위치 | N+2 | 축 (x₀,y₀) 격자 탐색 후 위 칸 반복 | **새로 만든다** (계획 4번) |
| S4 변형장 | 연속 | S4 Slicer(S³ 파이썬 재구현)를 **우리 모델**에 실행 | **시도** (계획 3번, 불확실) |
| S³ 변형장 | 연속 | S³ 저장소가 배포한 **결과물**(웨이포인트 법선)을 읽음 | 읽기 모듈 완성 (`conical/s3io.py`) |

**S4 가 사다리의 어느 칸인지** (노트북 `calculate_rotation_matrices` 로 확인, 예측을 적은 뒤
구조만 보탠 것): S4 는 사면체마다 **접선축**(ẑ×r̂) 둘레로 **스칼라 각**만큼 돌리고 이웃
차이를 벌해 매끈하게 한다. 균일 원뿔은 그 스칼라가 상수 θ, 우리 θ(z) 는 z 만의 함수,
S4 는 **θ(x,y,z)** 다. S³ 만이 회전축까지 자유(쿼터니언장)다. 즉

    평면 0 → θ 1 → θ(z) N → θ(x,y,z) [S4] → 쿼터니언장 [S³]

로, S4 는 우리 방법의 **직접 일반화**다. 사다리에서 S4 칸은 S³ 칸보다 한 칸 아래에 둔다.

S³ 본체는 Windows GUI + oneMKL + MeshLab 배치라 이 환경에서 못 돌린다. 대신 저장소에
모델 6개의 곡면 레이어 툴패스(점 + 국소 빌드 방향)가 통째로 들어 있어, **S³ 가 그
모델에 준 방향장을 그대로 읽는다.** 즉 S³ 칸은 "S³ 가 출판한 그대로" 다.

⚠ S³ 결과물은 모델에 따라 서포트+강도+표면품질을 **함께** 최적화한 것이라(README 의
`1.7 SF_SR_SQ`), 순수 서포트 천장이 아닐 수 있다. 어느 목적으로 만든 결과물인지는
저장소에 안 적혀 있다. 그래서 S³ 칸의 수치가 0 이 아니어도 "S³ 의 한계" 로 읽지
않는다.

## 2. 공통 자 (ruler)

**면 법선 n̂ 과 그 면의 국소 빌드 방향 b̂ 의 각이 45° 안이면 자기지지. 면적 가중 %.**

```
g = n̂ · b̂          서포트 필요 ⟺ g < κ = −sin 45°
```

* 우리 칸: b̂ = (sinθ·r̂, cosθ) → `analytic.py` 의 `n_z·cosθ + n_r·sinθ` 와 **같은 식**
  (`conical/s3io.py` `support_fraction_dirs`, `cone_dirs`. 평면에서 두 구현이
  12.45% = 12.45% 로 일치하는 것을 ring 으로 확인했다. 테스트가 고정한다)
* S³ 칸: b̂ = 그 면 중심에 **가장 가까운 웨이포인트**의 법선
* S³ 소스에서 확인한 S³ 자신의 규칙: `m_supportFreeAngle = 45.0`,
  `-n·printDir < -sin(45°)` (`DeformTet.cpp:1099, :2207`). **자가 같다.**
* **바닥 접촉 면은 양쪽에서 뺀다.** S³ 는 `isBottomTet` 의 면을 오버행에서 빼고, 우리
  해석식은 안 뺀다. 평평한 바닥은 어느 방법으로도 못 고치고 고칠 필요도 없으므로
  (베드가 받친다) 분모·분자에서 함께 제외한다. 규칙: 중심 z ≤ z_min + 0.3mm 이고
  n_z < −0.9. 영향: 우리 데모 모델 ≈1% (바닥이 점), S³ 모델은 teapot 12.4%,
  bunny 12.0%, ankleBase 18.8% (바닥이 평면).
* 툴패스 기반 '진짜 오버행' 은 **안 쓴다.** 검사기 A 가 3축 가정(수직 지지 창)이라
  곡면 레이어에 못 쓴다. 우리 칸에서만 참고 열로 적을 수 있으나 사다리 판정에는 안 넣는다.

### 달성률

```
A(칸) = (S_평면 − S_칸) / (S_평면 − S_천장)        S = 남은 서포트 %
```

A = 1 이면 그 칸이 천장과 같고, A = 0 이면 평면과 같다. 천장은 그 모델에서 쓸 수 있는
것(S³ 결과물 또는 S4 실행) 중 **낮은 쪽**이다.

### 고정한 설정

outward 만 (inward 는 5축 두 방식 모두 간섭 불안전 — README 17번). 최대각 44°.
k = 0.2, k_blend = 0.1, 층간격 상한 1.5. 축은 `center_on_axis`(바운딩박스 중심).
축 위치 칸만 축을 움직인다.

면은 n_r ≈ 0 이라 원뿔이 못 고친다. 축대칭 모델은 **S³ 묶음에 없다** — 우리 모델
쪽에서 채운다.

## 4. 천장 데이터가 유효하려면 (사전 조건)

이 조건이 깨지면 그 모델의 S³ 칸은 **무효**로 적고 비교에서 뺀다. 수치를 보고
조건을 완화하지 않는다.

| 조건 | 문턱 | 확인 결과 (문서 작성 시점) |
|---|---|---|
| 첫 층 법선 평균의 위 성분 \|·\| | ≥ 0.95 (첫 층이 평면) | 6/6 통과: 0.997~1.000 (부호 전부 −, 즉 저장된 벡터는 노즐 방향. `load_waypoints` 가 뒤집는다) |
| 면 중심 → 최근접 웨이포인트 거리 중앙값 | ≤ 1.0 mm | **아직 안 봄** |
| 같은 거리 95 분위 | ≤ 3.0 mm | **아직 안 봄** |
| S³ 칸 ≤ 평면 칸 | 항상 | **아직 안 봄** (S³ 가 평면보다 나쁘면 방향장 읽기가 틀린 것) |

## 5. 예측 (보기 전에 적음)

**H1. S³ 천장은 6 모델 모두 2% 이하.** 논문 주장이 support-free 이고 결과물은 실제로
출력한 것이다. 2% 를 넘으면 다목적(SR·SQ) 결과물이거나 매핑 오류다 — §4 로 가른다.

**H2. 균일 원뿔(서포트 최소)의 달성률 A.**

| 모델 | 예측 A(균일 최소) | 근거 |
|---|---|---|
| teapot | **0.5 ~ 0.7** | 몸통이 축대칭에 가깝고, 주둥이·손잡이 밑면은 n_r > 0 이라 outward 원뿔이 일부 고친다 |
| bunny_cut6 | 0.3 ~ 0.5 | 턱·귀 밑이 한쪽을 봄. 축이 몸통 중심이면 귀 밑은 n_r 부호가 갈린다 |
| armadillo4 | 0.3 ~ 0.5 | 팔·다리가 사방으로. 일부는 n_r > 0 |
| topopt_new4 | 0.2 ~ 0.4 | 가지 구조. 아래보기 면의 반이 축 쪽을 본다 |
| ring | **0.2 ~ 0.4** | 구멍 꼭대기(n_r ≈ 0)는 못 고침. 바깥 아래쪽만 고침 |
| AnkleBaseV1 | 0.3 ~ 0.5 | 형상 모름. 중간값 |

**H3. 밴드 N=2→4 의 추가 달성률은 모델당 0.10 이하.** 비축대칭 오버행은 **높이**로
갈리지 않고 **방위각**으로 갈린다. 높이 밴드는 틀린 축이다. teapot 만 예외 가능
(주둥이 높이와 몸통 밑면 높이가 다르다) — 거기서도 0.15 이하.

**H4. 축 위치 칸의 이득이 가장 큰 모델은 bunny 또는 topopt** (한쪽으로 몰린 돌출).
teapot 은 주둥이와 손잡이가 반대편이라 축을 옮겨도 하나를 얻고 하나를 잃는다 →
이득 0.05 이하. ring 은 축을 옮겨도 구멍 꼭대기가 n_r ≈ 0 인 건 같다 → 0.05 이하.

**H5. 우리 모델에서 S4 천장 = 0.0%** (균일 최대각과 동률). S4 가 돌지 않으면 빈칸.

**H6. 전체 그림.** 자유도 1(균일)에서 A 중앙값 0.3~0.5, N 을 올려도 거의 안 오르고,
축 위치에서 한 번 뛰고(bunny·topopt), 그래도 S³ 까지 **0.3 이상의 격차**가 남는다.
즉 "비축대칭 모델에서 θ(z) 는 S³ 의 절반 안팎을 자유도 1~3 으로 얻는다" 가 예상
결론이다. 이것이 맞으면 적용 범위 판별기(계획 3번)의 문턱은 **"균일 최소 칸이
평면 대비 절반 이상 줄이는가"** 에서 출발한다.

## 6. 판정 기준 (결과를 보고 바꾸지 않는다)

| 관찰 | 뜻 | 하는 일 |
|---|---|---|
| H2 가 위로 틀림 — A(균일) ≥ 0.7 이 4/6 이상 | 비축대칭에서도 경량으로 충분 | 적용 범위 판별기 문턱을 올린다. "S³ 의 절반" 이 아니라 "대부분" 으로 고쳐 적는다 |
| H2 가 아래로 틀림 — A(균일) ≤ 0.2 가 4/6 이상 | 원뿔 자유도가 비축대칭에 거의 무력 | 축 위치·θ(z,φ) 없이는 S³ 모델 부류를 **적용 범위 밖**으로 선언한다 |
| H3 가 틀림 — 어느 모델에서든 밴드 추가 이득 > 0.20 | 높이 밴드가 비축대칭에서도 값이 있다 (놀라움) | 왜 그런지 그 모델에서 밴드 경계와 오버행 높이 분포를 대조해 적는다 |
| H4 — 축 위치 이득 > 0.20 인 모델이 있음 | 다음 자유도는 θ(z,φ) 가 아니라 **축 선택**이 먼저 | 계획의 자유도 4번 순서를 바꾼다 |
| H4 — 축 위치 이득 < 0.05 가 6/6 | 축 위치 칸은 정보가 없다 | 사다리에서 그 칸을 뺀다 (코드는 남긴다) |
| S³ 칸이 평면보다 높은 모델 | 방향장 매핑 오류 | §4 로 무효 처리. **수치를 맞추려고 매핑을 손보지 않는다** |
| S³ 칸 2~10% | 다목적 결과물일 가능성 | 그대로 적고 "S³ 의 한계" 로 읽지 않는다 (§1 ⚠) |

**철회 조건.** H6 의 "절반 안팎" 이 6 모델 중 4 이상에서 밖(A < 0.2 또는 A > 0.8)이면
그 문장은 철회하고, 실측 분포를 그대로 쓴다. 모델 6 개는 표본이 작다 — **비율을 일반화
하지 않고** 모델별로 적는다.
