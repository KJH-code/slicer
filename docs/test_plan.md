## T1. 관례 각도 대 자동 결정 — "알고리즘이 없었다" 의 정량화

**질문.** 지금까지 사람들은 원뿔각을 관례로 골랐다(RotBot 45°, ZHAW·Slicer4RTN 3축 15~25°,
Slicer4RTN 기본 45°). 모델마다 다른 최적 각도를 고정값이 얼마나 놓치는가, 자동 결정은 그 손실을
얼마나 되찾는가.

**방법.**
- 팔(arm): 고정 15° · 20° · 25° · 45° / 자동 균일(J) / 자동 밴드2 / **사후 최적 균일**(모델마다 격자 전수로
  미지지 길이가 최소인 균일각 — 정답지 역할)
- 지표: 미지지 길이 mm, 평균 |θ|, 그리고 **후회(regret)** = 그 팔의 미지지 − 사후 최적의 미지지
- 베드 안전각(22.8°) 적용 유무 두 판. 45° 는 베드 상한 판에서 실현 불가로 표시

**사전 기준.**
- 자동 결정의 후회 중앙값이 어떤 고정 각도보다도 작다 → "자동 결정이 관례보다 낫다"
- 고정 각도 중 하나가 자동과 같거나 낫다면, 그 각도와 그 이유(표본이 특정 각도에 몰렸나)를 범위로 기록

**재료.** `analyze_gap_sample.py`(툴패스 측정 경로), `compare_ceiling.uniform_best`.

## T2. 층간격 식의 실측 검산 — 증명 B

**질문.** `간격 = h − r·(tanθₖ₊₁ − tanθₖ)` 가 실제로 내보낸 G-code 의 층 사이에서 맞는가.

**방법.**
- 밴드 프로필 G-code(램프 밴드2, 구 `[28,20]`, 허리3 ×2 등 블렌드가 있는 것)에서 `; layer N` 주석으로
  층을 나누고, 같은 반경 r 근처(±0.1mm)의 이웃 층 점 쌍에서 z 차를 잰다
- 예측: 층마다 θₖ 는 `CONICAL_META` 프로필에서 계산
- 상수각 파일에서는 간격 ≡ h 인지도 함께(대조군)

**사전 기준.** 측정 간격 / 예측 간격의 중앙값이 1 ± 0.02, 95% 구간이 1 ± 0.05 안.
벗어나면 어느 r·어느 층에서 벗어났는지(현 분할 오차, 블렌드 경계) 기록.

**의미.** 증명 B 의 검산이 "식 = 코드" 가 아니라 **"식 = 실제 출력 파일"** 이 된다.

## T3. 밴드 수의 최선해 곡선 — "몇 개를 써야 하나"

**질문.** J 가 고른 해가 아니라 **전수 탐색의 최선해**로 N = 1, 2, 3, (4) 를 비교하면
(증명 E(i) 의 단조성대로) 어디서 포화하는가.

**방법.**
- 해석식으로 N 마다 각도 격자 4°·경계 후보를 전수 탐색해 두 목적을 각각 최적화:
  ① 서포트 최소(동점은 평균 |θ| 작은 쪽) ② 서포트 동일 조건에서 평균 |θ| 최소
- 블렌드 폭은 증명 B 의 최소 폭을 그대로 강제
- 최선해만 G-code 로 내보내 툴패스로 확인
- 비용이 크면 N=3 은 경계를 등간격 + 허리 위치 후보로 제한하고 그 제한을 적는다

**사전 기준.**
- 해석식 최선 서포트가 N 에 대해 비증가 (증명 E(i) — 어기면 탐색 구현 결함으로 본다)
- 포화 N* 정의: N → N+1 에서 미지지 감소 < 0.5mm **그리고** 평균 |θ| 감소 < 1°
- 결과 문장: "모델 X 개에서 N* = 1, Y 개에서 N* = 2, …" — 보고서 4.2 의 답

## T4. 견고성 — 작은 변화에 결정이 흔들리나

**질문.** 실제 사용에서 생기는 작은 차이가 고른 각도를 바꾸는가.

**교란 축** (각각 한 축씩만 움직인다)
| 축 | 값 |
|---|---|
| 메시 해상도 | 원본 / 세분화 ×4 / 단순화 ×0.5 |
| 축 정렬 오차 | 중심 0.1·0.5mm 이동, 축 1°·3° 기울임 |
| 임계각 | 40° · 45° · 50° |
| 층고 | 0.2 · 0.3 · 0.4 |

**지표.** 고른 각도의 변화(°), 미지지 길이 변화(mm).

**사전 기준.** 메시 해상도·정렬 오차에서 각도 변화 ≤ 격자 한 칸(2°) 인 모델 비율을 보고.
임계각·층고는 '바뀌어야 정상'인 축이라 방향(예: 임계각↑ → 각도↓)이 맞는지만 본다.
균일각 정확 선택 세션에서 계단함수 때문에 argmax 가 튀는 것이 확인되면, 그 튐을 여기서 따로 센다.

## T5. 메시 예측 대 G-code 측정 — 예측 단계를 믿을 수 있나

**질문.** 알고리즘은 메시 해석식으로 각도를 고른다. 그 예측 순위가 실제 G-code 의 미지지 순위와 같은가.

**방법.** 모델마다 각도 0~44°(4° 격자) 균일 팔의 해석식 서포트 대 툴패스 미지지 길이 →
스피어만 순위상관. 기존 `compare_prediction_vs_toolpath.py` 를 최신 코드로 재실행·확장.

**사전 기준.** 모델별 ρ 중앙값 ≥ 0.8 이면 "예측 단계가 G-code 결과를 대표한다" 로 신뢰성 총정리에 넣는다.
낮은 모델은 원인(바닥 근처 신호, G3)을 적는다.

## T6. 증명 A·E(iii) 수치 확인

- **A:** 회전체(무작위 프로필 10개)를 만들어, 각 면의 유효 오버행을 **실제로 원뿔 층을 만든 뒤** 층 법선과의
  각으로 잰 값 대 "원래 오버행 − θ" 비교. 기준: 최대 차 < 0.01°
- **E(iii):** 알려진 곡면 층 z = Z′ − a·r − b·r² 에 접하는 원뿔(1차 근사)의 높이 오차를 r 에 따라 재서
  기울기 2 의 로그-로그 직선(오차 ∝ b·r²)인지 확인. S4 세션이 실제 층 곡률을 주면 그 값을 넣어
  모델별 '근사 오차 예측' 을 같이 낸다
