# 논문 일관성 설계

최종보고서(2026-11-11본), 12월 포스터, 발표 자료가 **같은 주장을 같은 범위와 같은 숫자로**
말하게 만드는 방법이다. 2026-11-11 보고서를 검토하다 발견한 불일치는 거의 모두 한 가지
원인에서 나왔다. **숫자가 옮겨 다니면서 그 숫자의 조건이 떨어져 나갔다.**

---

## 0. 원인 진단: 지금 불일치는 어디서 생겼나

| 증상 | 예 | 떨어진 조건 |
|---|---|---|
| 대표 수치가 출력 불가 영역의 값 | 초록 "평균 23°에서 33~48% 감소". 베드 상한은 22.79° | 베드 상한(없음) |
| 추정한 k에서는 성립하지 않는 결과 | 33~48%는 k=0.15~0.3 구간. 추정 k̂=0.06에서는 고정 40°가 우세 | k 범위 |
| 유리한 지표만 인용 | "16개 중 15개"는 %p 지표. 같은 툴패스의 mm 지표로는 5승 12무 | 지표 |
| 개발 표본 결과만 초록에 | 보류 표본에서는 3/21로 기각(IV.2.3) | 표본(개발/보류) |
| 검증 범위를 일반화 | "해석식 순위 = G-code 순위(ρ 0.956)"는 균일각만 검증. 밴드에서는 Table 9가 반대 | 프로필 종류(균일/가변) |
| 같은 기호, 다른 정의 | 보고서 k = 0.06/0.2(%p/°, J의 기울기 비용). 발표 7장 k ≈ 1.7~4.2(MLP 예측, IoU 라벨) | 정의 |
| 저장소 문서가 낡음 | `docs/verification.md`: "실물 출력은 이 연구의 범위 밖". 보고서 IV.4는 L1~L5 출력 | 시점 |

결론: 문장을 고치는 것만으로는 다시 깨진다. **숫자와 그 조건을 한곳에 두고, 모든 문서가
그곳을 참조하게 해야 한다.**

## 1. 구조: 원장 셋, 문서 하나의 흐름

```
results/*.json  ──(build_numbers.py)──▶  paper/numbers.yaml   수치 원장 (자동 생성)
                                              │
paper/glossary.yaml  용어·기호 원장 (사람)      │
                                              ▼
paper/claims.yaml    주장 원장 (사람) ── 각 주장이 수치 id·조건을 인용
        │
        ▼  (아래로만 전파)
  본문 IV 결과 → V 고찰 → VI 결론 → 국문 초록 → 1쪽 요약문 → Table 12 → 포스터·발표
        │
        ▼
  check_paper.py  ── 원고 텍스트를 원장과 대조해 불일치를 출력
```

원칙 셋.

1. **단일 출처.** 원고에 쓰는 숫자는 반드시 `numbers.yaml`에 id가 있어야 한다. 원고에서 숫자를 직접 고치지 않는다.
2. **조건은 숫자의 일부다.** 조건 다섯 개(§2)가 빠진 숫자는 원장에 들어가지 못한다.
3. **위에서 아래로만 고친다.** 초록을 먼저 고치고 본문을 맞추지 않는다. 본문 결과 → 결론 → 초록 순서다.

## 2. 수치 원장 `paper/numbers.yaml`

### 필수 조건 다섯 개

모든 실험 수치는 이 다섯 가지를 가진다. 해당이 없으면 `-`로 명시한다(빈칸 금지).

| 키 | 값 | 이번 불일치에서 빠졌던 것 |
|---|---|---|
| `sample` | `dev21` / `holdout21` / `ext33` / `print` | A1 보류 표본 |
| `layer` | `0.3` / `0.4` / `0.2-0.5` | Table 7 0.4mm 반전 |
| `support_model` | `optimistic` / `pessimistic` / `analytic` | Table 7 (c) |
| `bed_limit` | `none` / `22.79` | B1 23° 대표 수치 |
| `k` | `0.2` / `0.06` / `sweep:0.15-0.3` / `-` | B2 |

여기에 `metric`(미지지 mm / 진짜 오버행 %p / 해석식 S % / 시간)과 `profile`(uniform / band2 / N1-4)을 붙인다.

### 항목 예

```yaml
tradeoff_gain_03:
  value: 48            # %
  text: "48% 감소(1133 → 588 mm)"
  metric: unsupported_mm
  profile: auto_uniform_vs_fixed
  sample: dev21
  layer: 0.3
  support_model: optimistic
  bed_limit: none        # ← 초록에 쓰려면 이 조건이 문장에 함께 나와야 한다
  k: "sweep, 평균 |θ| 23° 지점"
  source: {script: analyze_k.py, json: k_results.json, key: "tradeoff.layer03.mean23"}
  commit: <해시>
  figure: Fig.7a

band_win_holdout:
  value: "3/21"
  verdict: 사전 기준 기각
  sample: holdout21
  ...
```

### 생성

- `tools/build_numbers.py`가 `*_results.json`을 읽어 `paper/numbers.yaml`을 **다시 만든다.**
  지금 루트에 있는 JSON 8개(`compare_bands_results.json`, `layer_height_results.json`,
  `rho_gap_results.json` 등)가 출발점이다.
- JSON이 없는 결과(Table 2 출력 시간, Table 10 S4, Table 11 실물)는
  `paper/numbers_manual.yaml`에 손으로 적는다. `source`에 측정 기록 위치(사진·노트 쪽수)를 남긴다.
- 실험을 다시 돌리면 JSON → 원장 → `check_paper.py` 순서로 영향받는 문장이 전부 드러난다.
  예를 들어 판정 문턱을 60°로 바꿔 다시 돌리면, 바뀐 숫자를 인용한 문장 목록이 나온다.

## 3. 주장 원장 `paper/claims.yaml`

초록·요약문·결론·Table 12·포스터에 들어가는 주장 문장의 **정본**이다. 문서마다 문장을 새로 쓰지 않고,
여기 적힌 문장을 길이만 줄여서 쓴다. 줄일 때도 `scope`의 한정어는 지우지 않는다.

```yaml
C3_band:
  sentence: >
    허리가 있는 형상에서, 두 구간 각도는 같은 서포트를 평균 8.4° 적은 기울기로 얻는다.
  scope: [허리 있는 형상, 층고 0.3mm, 낙관 지지]
  must_mention:                     # 이 주장을 쓰는 모든 문서에 함께 있어야 하는 것
    - band_win_holdout              # 보류 표본 3/21(허리형 3/3)
    - band_reverse_04_pes           # 0.4mm 비관에서 반전
  evidence: [table7_c_03_opt, table7_b, fig9]
  status: 조건부                     # 지지 / 조건부 / 지지 부족 / 기각
  physical: 미검증 (L3 예측 차 0.05%p, 판별 불가로 설계됨)
```

### 2026-11-11본 기준 정본 문장 (제안)

| id | 정본 문장 | 상태 |
|---|---|---|
| C1 | 원본 면 법선의 해석식 하나로 서포트를 판정하며, 최적 각은 면이 고쳐지는 근만 평가해 정확히 얻는다 | 지지 |
| C2 | 기울기 비용 k가 0.15~0.3일 때, 모델별 자동 결정은 같은 평균 기울기의 고정각보다 미지지를 줄인다(베드 상한 없이 33~48%, 상한 22.79°에서는 ○○%). 기울기 비용이 없으면 고정 45°가 낫다 | 조건부 |
| C3 | 허리가 있는 형상에서 두 구간 각도는 같은 서포트를 평균 8.4° 적은 기울기로 얻는다. 보류 표본에서는 허리형 3/3만 이겼다 | 조건부 |
| C4 | 각도 비용 k는 데이터로 0.06(95% 0.055~0.08)으로 추정되나 층고에 따라 다르며, 본문 기본값 0.2는 '1° = 미지지 2~5mm'라는 가치판단이다 | 지지(추정)·가치판단(기본값) |
| C5 | 균일각에서 해석식의 각도별 순위는 G-code 툴패스 순위와 일치한다(ρ 중앙 0.956). 가변각 프로필에서는 해석식이 층간격 팽창을 모른다 | 조건부 |
| C6 | 해석식은 구간이 많을수록 좋다고 하지만 G-code 미지지는 N≥3에서 커지므로, 구간 수는 툴패스 검사로 상한을 둔다(이 표본에서 N≤2) | 지지 |
| C7 | S4가 수렴한 모델(구·torus)에서 원뿔족의 서포트는 같거나 낮았고, 각도 결정 단계는 S4 전체 실행보다 약 450~1,200배 빨랐다 | 조건부(n=2) |
| P | 실물에서 치수와 평면 대비 서포트 판정은 맞았고, 압출 모형과 45° 문턱은 틀렸다(조건별 1회) | 지지(n=1) |

`○○`은 아직 원고에 없는 수치다. Fig. 7 (c)(d)에서 뽑아 원장에 넣어야 한다.

## 4. 용어·기호 원장 `paper/glossary.yaml`

같은 말이 문서마다 다른 것을 가리키지 않게 정의를 하나로 묶는다. 겹치면 **기호를 바꾼다.**

| 용어 | 정의 (보고서) | 충돌 | 조치 |
|---|---|---|---|
| k | J = ΔS − k·\|θ\|의 기울기 비용, 단위 %p/° | 발표 7장의 MLP 예측 k(IoU 라벨, 값 1.7~4.2) | 발표 쪽을 `k_IoU` 등으로 바꾸거나 "다른 목적함수"라고 명시 |
| 미지지 길이 | 검사기 A에서 지지 판정을 못 받은 경로 길이(mm) | "서포트", "오버행"과 섞여 쓰임 | 지표 세 개를 고정: 해석식 S(%), 미지지(mm), 진짜 오버행(%p) |
| 균일 | 모델 전체에 각 하나 | "J 균일 / 아래 구간 각과 같은 균일 / 등왜곡 균일" 세 가지 | 기준선 (a)(b)(c)를 항상 이름으로 부름 |
| 후회 | 사후 최적 대비 미지지 증가(mm) | — | 고정 |
| 45° 문턱 | 해석식의 κ=−sin45° | 검사기 A의 실효 문턱 atan(0.45/h), 실물 60° | 문장에서 "선택기 문턱 / 검사기 문턱 / 실측 문턱"으로 구분 |
| 사전 등록 | 결과 전에 판정 기준을 git에 커밋 | — | 사후 분석은 '사후' 표기 유지 |

## 5. 문서 계층과 전파 순서

```
① 원장(numbers, claims, glossary)
② 본문 IV 결과        ← 숫자를 원장에서만 가져온다
③ V 고찰               ← 한계·불일치를 여기서 전부 말한다
④ VI 결론              ← claims.yaml 문장 그대로
⑤ 국문 초록            ← 결론의 축약. must_mention 유지
⑥ 1쪽 연구결과 요약문  ← 초록과 같은 숫자
⑦ Table 12 신뢰성 정리 ← 각 행의 '범위·단서'가 claims.scope와 같아야 함
⑧ 포스터·발표          ← ⑤를 근거로. 새 숫자 금지
```

**하위 문서에는 상위 문서에 없는 숫자를 넣지 않는다.** 포스터에 새 그래프가 필요하면
본문(②)에 먼저 넣거나, 최소한 원장(①)에 등록한다.

## 6. 자동 검사 `tools/check_paper.py`

원고(hwpx는 hwpx 플러그인으로 텍스트를 뽑고, PDF는 `pdftotext`)를 읽어 다섯 가지를 검사한다.

| 검사 | 규칙 | 이번 원고에서 잡혔을 것 |
|---|---|---|
| R1 등록되지 않은 숫자 | 원고의 숫자(%, mm, °, n/m, ρ 등) 중 원장 `text`·`value`와 맞지 않는 것 | 계산 실수, 옛 실행의 숫자 |
| R2 같은 양, 다른 값 | 같은 id가 문서 위치마다 다른 값 | "16개 중 15개" ↔ "15/16" ↔ Table 7 |
| R3 조건 동반 | `bed_limit: none`인 수치가 초록·결론에 나오면 같은 문장에 "상한 없이"류 표현 필요. `sample: dev21`이면 보류 표본 언급 필요 | B1, A1 |
| R4 must_mention | 주장을 쓴 문서 단위(초록, 결론, 포스터)마다 동반 항목이 있는지 | 보류 표본 누락 |
| R5 금지 표현 | "검증했다/증명했다"를 계산 결과에 쓰면 경고. 실물 근거(`sample: print`)가 있을 때만 허용 | RQ2 "신뢰성 검증" 과대 |

출력은 `위치(쪽·절) / 문장 / 규칙 / 원장 id / 제안` 표다. 0건이 제출 기준선이다(테스트·ruff와 같은 방식).

## 7. 운영 규칙

1. **실험을 다시 돌리면** JSON 커밋 → `build_numbers.py` → `check_paper.py` → 걸린 문장을 ②부터 아래로 고친다.
2. **결과가 사전 기준을 못 넘으면** claims의 `status`를 먼저 바꾼다(지지 → 조건부/기각). 문장은 그 뒤에 고친다.
3. **팀원 세 명의 역할:** 원장 담당 1명(숫자·조건 등록), 본문 담당 1명, 하위 문서(초록·요약·포스터) 담당 1명. 하위 문서 담당은 원장에 없는 숫자를 받으면 되돌려 보낸다.
4. **저장소 문서도 같은 계층에 넣는다.** `docs/verification.md`의 "실물 출력은 범위 밖"처럼 낡은 문장은 원장 갱신 때 함께 고친다.
5. **마감 전 점검:** `check_paper.py` 0건 + claims `status`와 초록 어조가 맞는지를 사람이 한 번 더 읽는다.

## 8. 착수 순서 (현재 원고 기준)

| 순서 | 작업 | 결과물 | 비고 |
|---|---|---|---|
| 1 | claims.yaml 작성(§3 표) | 정본 문장 8개 | 계산 없음 |
| 2 | glossary.yaml 작성, 발표 자료의 k와 기호 분리 | 용어 표 | 계산 없음 |
| 3 | numbers_manual.yaml에 원고의 숫자 전부 등록 | 원장 초판 | 먼저 손으로, 자동화는 나중 |
| 4 | 비어 있는 수치 채우기: 상한 22.79°에서의 Fig.7 이득 | `○○%` | 기존 결과에서 추출 |
| 5 | 원고 수정: 결론 → 초록 → 요약문 → Table 12 | 수정본 | §5 순서 |
| 6 | check_paper.py (R2·R3·R4부터) | 검사 0건 | R1은 원장이 다 찬 뒤 |
| 7 | build_numbers.py | 자동 원장 | 재실험(60° 문턱) 전에 필요 |

1~5만 해도 2026-11-11본에서 찾은 불일치(초록 4건, 결론 2건, 교차 문서 2건)는 모두 해결된다.
6~7은 12월 포스터와 이후 재실험에서 같은 일이 반복되지 않게 하기 위한 것이다.
