# 검증 계층 (verification hierarchy)

이 프로젝트의 결과가 "맞다"는 근거를 층으로 쌓는다. 각 층이 무엇을 보증하고
무엇을 보증하지 **못하는지**를 명시한다.

| 층 | 도구 | 보증하는 것 | 보증하지 못하는 것 |
|---|---|---|---|
| ① Python 단위테스트 | `tests/` 8종 | 수식 구현의 자기 일관성 (왕복<1e-9, 상수=고정각, w_min 검출 등) | 수식 자체가 물리적으로 맞는지 |
| ② Python 툴패스 검사 | `toolpath_check.py`, `compare_prediction_vs_toolpath.py` | 예측과 독립 지표(툴패스 지지)의 경향 일치 (ρ=1.0), 이상적 추정의 결함 검출(층간격 팽창) | 검사기와 예측기가 같은 가정을 공유해 함께 틀렸을 가능성 |
| ③ 브라우저 독립 재구현 대조 | 시뮬레이터 '검증' 탭 | 문서의 수식만으로 처음부터 재구현한 JS가 Python 과 점 단위 일치 (funnel 26,727점 100.0000%, 미지지% 소수 3자리 동일) | ⚠ 두 구현 모두 같은 AI 도구로 작성 — **완전 독립 아님** |
| ④ 사람 손계산 | 검증 탭 '점 클릭 → 숫자 대입식' | 임의의 점 하나를 계산기로 따라쳐서 확인 가능 — AI 무관한 최종 검산 경로 | 전수 검사 아님 (표본 검산) |
| ⑤ 실물 출력 (향후) | 3축 소각도 → Open5x | 기하 판정이 무시한 물리(브리징·수축·접착) | — |

## ③ 검증 탭 사용법

1. `tools/slicing_simulator.html` 브라우저로 열기 → **검증** 탭 (CDN 차단/오프라인에서도 동작 — Canvas2D 전용)
2. `conical_slice.py` 출력 G-code 로드 (`;CONICAL_META` 헤더 자동 인식)
3. (선택) `toolpath_check.py G.gcode --export-json truth.json` 정답지 로드 → 점 단위 대조
4. 3D 색칠: **층간격 히트맵**(파랑=정상, 빨강=팽창/지지 없음) / 미지지 구간
5. 차트: 층별 미지지 막대 / **프로필 인스펙터** — 층간격 배율 |1−c·r·s| 해석식 곡선(주황) 위에 실측 산점(초록)
6. **점 클릭** → 숫자 대입 손계산 (r, θ(Z′) 구간·s·T, 역변환 z, 배율, 지지 판정 + 원본 G-code 행)
7. "브라우저 자체 테스트" 버튼 → 왕복/상수=고정각/합성 지지/가역성 경계 4종 PASS·FAIL

### 결함 수정 (2026-09-08): 층간격 제약 + 압출 종류 분리

검사기가 잡아낸 두 결함을 실제로 고치고, 같은 검사기로 재측정했다.

**① 층간격 제약** — 가역성 조건(`c·r·s<1`)은 배율 `m = 1 − c·r·s` 가 0 이하로
가는 것만 막는다. 각도가 감소하는 안정 방향은 가역성엔 안 걸리면서 m 이 커진다.
배율을 `[1/limit, limit]` 안에 두는 최소 블렌드 폭을 닫힌 식으로 유도해
(`w ≥ r_b·|Δtan|/(limit−1)`, 팽창 분기) `from_bands` 에 넣었다. 반경은 전 모델
최대가 아니라 **그 높이의 최대 반경** `r_b` (`meshio.RadiusProfile`) 를 쓴다 —
그래야 경계를 반경이 작은 높이로 옮기는 것이 이득이 된다.
(경계 배치 비용은 아래 '복잡도 곡선 재작성' 절에서 `w·r_b` 로 한 번 더 교정된다.)

**② 압출 종류 분리** — 내장 슬라이서의 희소 인필은 레이어마다 0/90° 로 방향이
바뀌어 '아래에 아무것도 없는' 구간이 원래 많다(브리징으로 정상 출력). 전체
미지지%가 여기 지배당해 표면 지지를 가리고 있었다(램프 모델에서 전체 기준으로는
균일각이 이기는데 페리미터 기준으로는 밴드가 3.6배 이겼다). Slic3r/PrusaSlicer
관례의 `;TYPE:` 주석을 내보내고 검사기가 페리미터/인필을 갈라 보고한다.
지지 판정 자체는 **퇴적된 모든 재료**로 하고(인필도 실제로 받쳐준다), 종류는
보고에만 쓴다.

재측정 (`compare_waist.py`, 페리미터 미지지 %):

| 모델 | 평면 0° | 균일(J) | 밴드2 (제약 없음) | 밴드2 (제약) |
|---|---|---|---|---|
| 구 (허리 없음) | 7.51% | **1.08%** (28°) | 7.35% (블렌드 0.5mm, 15.5배) | 4.93% (14.5mm, 1.50배) |
| 램프 (허리 있음) | 4.49% | 3.01% (24°) | 2.40% (0.5mm, 5.8배) | **0.83%** (2.3mm, 1.50배) |

- 층간격 제약은 두 모델 모두에서 밴드를 개선한다 (7.35→4.93, 2.40→0.83).
- **밴드가 균일각을 이기는 조건이 드러났다**: 각도 변경의 가격이 그 높이의
  반경에 비례하므로, '허리'가 있어야 싸게 바꿀 수 있다. 구는 어디나 뚱뚱해
  블렌드가 모델 높이의 73%를 잡아먹고 균일각에 진다 — 정직하게 보고할 한계다.
- 램프에서는 경계가 자동으로 목(그 높이 반경 2.0mm)으로 옮겨가 블렌드가
  2.3mm 로 끝난다 — 등간격 경계 z=15 는 구 어깨(r≈3.9)라 훨씬 비싸다.

### 결함 수정 ③ (2026-09-08): 선택 단계가 블렌드 비용을 몰랐다

층간격 제약을 넣어도 구에서는 밴드가 균일각에 계속 졌다(4.93% vs 1.08%).
원인은 **선택 단계**였다: `select_banded` 는 밴드마다 독립적으로 각도를 고르고,
블렌드는 그 뒤에 프로필을 만들 때 붙는다 — 각도 변경의 가격을 J 가 아예 모른다.
게다가 `support_fraction_profile` 은 면을 '그 높이의 국소 원뿔각'과만 비교하므로
블렌드의 층간격 팽창을 **원리적으로 볼 수 없다**(구 프로필을 서포트 0.5%로 예측).

수정: 밴드 각도를 프로필 단위 J 로 공동 선택한다(`select_banded_j`). 후보 각도로
실제 프로필을 만들어(층간격 제약·경계 이동 포함) J 를 재고, 해석식이 못 보는
몫을 명시적 항으로 더한다:

```
J = (서포트 감소 %p) − k×평균|θ| − k_blend × Σ(블렌드 구간 표면적 %)×(m−1)/(limit−1)
```

- 탐색은 좌표하강(밴드 하나씩 다시 고르기)이라 밴드 수에 선형이다.
- ⚠ 좌표하강만으로는 균일해를 놓친다(실측): 구에서 `[36°,0°]` → 균일 `[36°,36°]`
  로 가려면 두 밴드를 동시에 바꿔야 하는데 중간 상태가 블렌드 비용을 다 물어
  `[2°,2°]` 같은 국소 최적에 갇혔다. 균일 후보를 전수 평가해 섞어서 막았고,
  덕분에 **결과가 최선 균일 원뿔보다 나쁠 수 없다**는 성질이 생겼다.
- `k_blend` 기본값 0.5 는 `analyze_blend_k.py` 의 창 분석에서 나왔다. 두 모델의
  정답(구=균일, 램프=부위별)을 동시에 맞히는 구간은 **0.1 ~ 1.5**. k_blend=0 이면
  구가 `[36°, −8°]`(방향 전환, 블렌드 비용 86.1)를 골라 병리적이다.

재측정 (페리미터 미지지 % / 면적가중 평균 왜곡각):

| 모델 | 평면 | 균일(J) | 밴드2 (제약만) | 밴드2 (제약 + J 블렌드비용) |
|---|---|---|---|---|
| 구 | 7.51% / 0° | **1.08% / 28°** | 4.93% / 18.9° | **1.08% / 28°** (균일로 수렴) |
| 램프 | 4.49% / 0° | 3.01% / 24° | 0.83% / 18.6° | **1.78% / 16.3°** |

램프에서 J 해가 제약만 쓴 해(0.83%)보다 페리미터가 높은 것은 결함이 아니라
**각도 비용 k 가 일한 결과**다 — 툴패스 지표는 서포트만 세고 왜곡은 안 세므로
항상 큰 각도를 선호한다. 두 축을 같이 보면 J 해는 균일각을 **서포트 1.7배·
왜곡 32% 로 동시에 지배**한다(파레토 우세; 밴드를 4개까지 늘리면 1.9배·38%). 두 밴드 해는 같은 프론티어 위의
다른 점이고, 어디에 설지는 k 가 정한다.

### 복잡도 곡선 재작성 (2026-09-08): 밴드 수 N=1~4

`compare_bands.py` — 기존 `compare_complexity.py` 의 '이상적 추정' 대신, 프로필 J 로
각도를 고르고 실제 파이프라인을 돌려 **페리미터 미지지 %** 로 잰다.

**단조성이 점검 기준이다.** N개 밴드는 이웃을 같은 각도로 두면 N−1개를 흉내낼 수
있으므로 J 는 N 에 대해 비감소여야 한다. 처음 돌렸을 때 램프에서 N=2(3.30) >
N=3(2.93) > N=4(2.33) 로 **감소**했고, 이 위반을 따라가 결함 셋을 찾았다.

| 결함 | 증상 | 원인 | 수정 |
|---|---|---|---|
| ① 단일 좌표 이웃 | N=4가 `[24,24,0,0]`(=N=2의 답)에 도달 못 함 | 블렌드 비용은 '이웃 밴드의 각도가 다른 자리'에 붙으므로 한 칸씩 바꾸면 중간 상태가 비용을 다 문다 | 이웃을 **연속한 밴드 덩어리**로 (크기 1 블록을 포함하므로 상위집합) |
| ② 이동 예산이 N에 의존 | N이 커질수록 허리에 못 닿음 | `max_shift = 밴드 높이 × 비율 = h/N` | **모델 높이 기준**으로 (허리까지의 거리는 몇 개로 나눴는지와 무관) |
| ③ 필요 폭을 가용 폭으로 잘라 반환 | 폭 **0.14mm 에 42°→0°**, 층간격 배율 **53.7배**, J=5.72인데 툴패스 5.74% | 자리가 없는 중심이 '폭이 작아 싸다'로 평가되고, `w == avail` 이라 '자리 부족 → 각도 삭감' 검사가 안 걸림 | 진짜 필요 폭을 반환, 자를지는 호출부가 결정 |

추가로 배치 비용을 J 와 정렬했다: `w + |이동거리|` → **`w · r_b`**(블렌드 겉넓이
proxy). J 가 무는 것은 '블렌드 구간의 표면적 × risk' 인데 폭만 보면 "같은 폭이라도
뚱뚱한 높이에서는 표면적이 훨씬 크다"를 놓친다. 이동거리 항은 J 에 대응물이 없는
임의 항이라 동점 처리로 내렸다.

그리고 **안전망**: `select_banded_j` 가 층간격 제약을 어긴 프로필은 J 와 무관하게
탈락시킨다. 계획기에 버그가 있어도 '예측은 최고인데 못 찍는' 해가 뽑히지 않는다.

수정 후 (페리미터 미지지 % / 면적가중 평균 왜곡각):

| N | 구 (허리 없음) | 램프 (허리 있음) |
|---|---|---|
| 1 (균일) | 1.08% / 28.0° | 3.01% / 24.0° |
| 2 | 1.08% / 28.0° | 1.78% / 16.3° |
| 3 | 1.08% / 28.0° | 1.78% / 16.3° |
| 4 | 1.08% / 28.0° | **1.57% / 14.8°** |

- 구는 N 과 무관하게 균일 28° 로 수렴한다 — 블렌드가 비싸 나눌 이유가 없다.
- 램프는 N 이 늘수록 좋아진다(J 증분 +0.963, −0.000, +0.209). N=3 이 N=2 와 같은 값인
  것은 밴드 경계(linspace)가 달라도 전이가 결국 같은 목으로 가기 때문이다.
- ⚠ **J 지형이 평평한 구간이 있다**: 램프 N=2 에서 `[24°,0°]`(J=3.290)와
  `[24°,4°]`(J=3.295)를 0.005 차이로만 구분한다. 툴패스로는 전자가 낫다(1.44% vs 1.78%).
  둘 중 무엇이 뽑히는지는 사실상 임의다.
- ⚠ 툴패스 최소는 `[30°,0°]`(0.83%)인데 J 는 이걸 안 고른다(J=3.121). 결함이 아니라
  **각도 비용 k 가 일한 결과**다 — 툴패스 지표는 서포트만 세고 왜곡(18.6° vs 14.9°)은
  안 센다. 어느 점을 고를지는 k 가 정한다.
