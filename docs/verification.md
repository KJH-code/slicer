# 검증 계층 (verification hierarchy)

이 프로젝트의 결과가 "맞다"는 근거를 층으로 쌓는다. 각 층이 무엇을 보증하고
무엇을 보증하지 **못하는지**를 명시한다.

⚠ **실물 출력은 이 연구의 범위 밖이다**(장비·여건상 불가능). 그래서 마지막 층은
'프린트해 봤다'가 아니라 **'같은 수식을 다른 사람이 따로 구현한 코드와 맞다'**이다.
물리(브리징·수축·접착)는 끝내 검증되지 않으므로, 모든 결론은 '증명'이 아니라
'시뮬레이션 경향'으로만 쓴다 — 이 제약을 감추지 않는 것이 이 문서의 목적이다.

| 층 | 도구 | 보증하는 것 | 보증하지 못하는 것 |
|---|---|---|---|
| ① Python 단위테스트 | `tests/` 15종 | 수식 구현의 자기 일관성 (왕복<1e-9, 상수=고정각, w_min 검출, 밴드 경계 겹침, 오버행/허상 분리 등) | 수식 자체가 물리적으로 맞는지 |
| ② Python 툴패스 검사 | `toolpath_check.py`, `compare_prediction_vs_toolpath.py` | 예측과 독립 지표(툴패스 지지)의 경향 일치 (ρ=1.0), 이상적 추정의 결함 검출(층간격 팽창) | 검사기와 예측기가 같은 가정을 공유해 함께 틀렸을 가능성. ⚠ 검사기 자신이 오버행이 아닌 것(희소 인필 위)을 섞어 세던 결함 → 2026-09-19 절, `support_breakdown` 으로 분리 |
| ③ 브라우저 독립 재구현 대조 | 시뮬레이터 '검증' 탭 | 문서의 수식만으로 처음부터 재구현한 JS가 Python 과 점 단위 일치 (funnel 26,727점 100.0000%, 미지지% 소수 3자리 동일) | ⚠ 두 구현 모두 같은 AI 도구로 작성 — **완전 독립 아님** |
| ④ 사람 손계산 | 검증 탭 '점 클릭 → 숫자 대입식' | 임의의 점 하나를 계산기로 따라쳐서 확인 가능 — AI 무관한 최종 검산 경로 | 전수 검사 아님 (표본 검산) |
| ⑤ 팀메 독립 구현 대조 | `compare_with_teammate.py` | 같은 수식을 **다른 사람이 따로 구현한 코드**와 면 단위 일치 (22,000면, 최대 차이 1.42e-14°) | 두 사람이 같은 오해를 했을 가능성 |
| ~~⑥ 실물 출력~~ | — | — | **⚠ 이 연구에서는 불가능하다** (장비·여건). 기하 판정이 무시한 물리(브리징·수축·접착)는 끝내 검증되지 않는다 — 결론을 '경향'으로만 쓰는 이유. |

## ③ 검증 탭 사용법

1. `tools/slicing_simulator.html` 브라우저로 열기 → **검증** 탭 (CDN 차단/오프라인에서도 동작 — Canvas2D 전용)
2. `conical_slice.py` 출력 G-code 로드 (`;CONICAL_META` 헤더 자동 인식)
3. (선택) `toolpath_check.py G.gcode --export-json truth.json` 정답지 로드 → 점 단위 대조
4. 3D 색칠: **층간격 히트맵**(파랑=정상, 빨강=팽창/지지 없음) / 미지지 구간
5. 차트: 층별 미지지 막대 / **프로필 인스펙터** — 층간격 배율 |1−c·r·s| 해석식 곡선(주황) 위에 실측 산점(초록)
6. **점 클릭** → 숫자 대입 손계산 (r, θ(Z′) 구간·s·T, 역변환 z, 배율, 지지 판정 + 원본 G-code 행)
7. "브라우저 자체 테스트" 버튼 → 왕복/상수=고정각/합성 지지/가역성 경계 4종 PASS·FAIL

### 결함 수정 (2026-09-08): 층간격 제약 + 압출 종류 분리

검사기가 잡아낸 두 결함을 실제로 고치고, 같은 검사기로 재측정했다.

**① 층간격 제약** — 가역성 조건(`c·r·s<1`)은 배율 `m = 1 − c·r·s` 가 0 이하로
가는 것만 막는다. 각도가 감소하는 안정 방향은 가역성엔 안 걸리면서 m 이 커진다.
배율을 `[1/limit, limit]` 안에 두는 최소 블렌드 폭을 닫힌 식으로 유도해
(`w ≥ r_b·|Δtan|/(limit−1)`, 팽창 분기) `from_bands` 에 넣었다. 반경은 전 모델
최대가 아니라 **그 높이의 최대 반경** `r_b` (`meshio.RadiusProfile`) 를 쓴다 —
그래야 경계를 반경이 작은 높이로 옮기는 것이 이득이 된다.
(경계 배치 비용은 아래 '복잡도 곡선 재작성' 절에서 `w·r_b` 로 한 번 더 교정된다.)

**② 압출 종류 분리** — 내장 슬라이서의 희소 인필은 레이어마다 0/90° 로 방향이
바뀌어 '아래에 아무것도 없는' 구간이 원래 많다(브리징으로 정상 출력). 전체
미지지%가 여기 지배당해 표면 지지를 가리고 있었다(램프 모델에서 전체 기준으로는
균일각이 이기는데 페리미터 기준으로는 밴드가 3.6배 이겼다). Slic3r/PrusaSlicer
관례의 `;TYPE:` 주석을 내보내고 검사기가 페리미터/인필을 갈라 보고한다.
지지 판정 자체는 **퇴적된 모든 재료**로 하고(인필도 실제로 받쳐준다), 종류는
보고에만 쓴다.

재측정 (`compare_waist.py`, 페리미터 미지지 %):

| 모델 | 평면 0° | 균일(J) | 밴드2 (제약 없음) | 밴드2 (제약) |
|---|---|---|---|---|
| 구 (허리 없음) | 7.51% | **1.08%** (28°) | 7.35% (블렌드 0.5mm, 15.5배) | 4.93% (14.5mm, 1.50배) |
| 램프 (허리 있음) | 4.49% | 3.01% (24°) | 2.40% (0.5mm, 5.8배) | **0.83%** (2.3mm, 1.50배) |

- 층간격 제약은 두 모델 모두에서 밴드를 개선한다 (7.35→4.93, 2.40→0.83).
- **밴드가 균일각을 이기는 조건이 드러났다**: 각도 변경의 가격이 그 높이의
  반경에 비례하므로, '허리'가 있어야 싸게 바꿀 수 있다. 구는 어디나 뚱뚱해
  블렌드가 모델 높이의 73%를 잡아먹고 균일각에 진다 — 정직하게 보고할 한계다.
- 램프에서는 경계가 자동으로 목(그 높이 반경 2.0mm)으로 옮겨가 블렌드가
  2.3mm 로 끝난다 — 등간격 경계 z=15 는 구 어깨(r≈3.9)라 훨씬 비싸다.

### 결함 수정 ③ (2026-09-08): 선택 단계가 블렌드 비용을 몰랐다

층간격 제약을 넣어도 구에서는 밴드가 균일각에 계속 졌다(4.93% vs 1.08%).
원인은 **선택 단계**였다: `select_banded` 는 밴드마다 독립적으로 각도를 고르고,
블렌드는 그 뒤에 프로필을 만들 때 붙는다 — 각도 변경의 가격을 J 가 아예 모른다.
게다가 `support_fraction_profile` 은 면을 '그 높이의 국소 원뿔각'과만 비교하므로
블렌드의 층간격 팽창을 **원리적으로 볼 수 없다**(구 프로필을 서포트 0.5%로 예측).

수정: 밴드 각도를 프로필 단위 J 로 공동 선택한다(`select_banded_j`). 후보 각도로
실제 프로필을 만들어(층간격 제약·경계 이동 포함) J 를 재고, 해석식이 못 보는
몫을 명시적 항으로 더한다:

```
J = (서포트 감소 %p) − k×평균|θ| − k_blend × Σ(블렌드 구간 표면적 %)×(m−1)/(limit−1)
```

- 탐색은 좌표하강(밴드 하나씩 다시 고르기)이라 밴드 수에 선형이다.
  → ⚠ **이 줄은 이후 무효가 됐다.** 아래 결함 ①에서 이웃을 '연속한 밴드 덩어리'로
    바꾸면서 블록이 `N(N+1)/2` 개가 되어 O(N²) 이다 (2026-09-18 절에 실측).
- ⚠ 좌표하강만으로는 균일해를 놓친다(실측): 구에서 `[36°,0°]` → 균일 `[36°,36°]`
  로 가려면 두 밴드를 동시에 바꿔야 하는데 중간 상태가 블렌드 비용을 다 물어
  `[2°,2°]` 같은 국소 최적에 갇혔다. 균일 후보를 전수 평가해 섞어서 막았고,
  덕분에 **결과가 최선 균일 원뿔보다 나쁠 수 없다**는 성질이 생겼다.
- `k_blend` 기본값 0.5 는 `analyze_blend_k.py` 의 창 분석에서 나왔다. 두 모델의
  정답(구=균일, 램프=부위별)을 동시에 맞히는 구간은 **0.1 ~ 1.5**. k_blend=0 이면
  구가 `[36°, −8°]`(방향 전환, 블렌드 비용 86.1)를 골라 병리적이다.

재측정 (페리미터 미지지 % / 면적가중 평균 왜곡각):

| 모델 | 평면 | 균일(J) | 밴드2 (제약만) | 밴드2 (제약 + J 블렌드비용) |
|---|---|---|---|---|
| 구 | 7.51% / 0° | **1.08% / 28°** | 4.93% / 18.9° | **1.08% / 28°** (균일로 수렴) |
| 램프 | 4.49% / 0° | 3.01% / 24° | 0.83% / 18.6° | **1.78% / 16.3°** |

램프에서 J 해가 제약만 쓴 해(0.83%)보다 페리미터가 높은 것은 결함이 아니라
**각도 비용 k 가 일한 결과**다 — 툴패스 지표는 서포트만 세고 왜곡은 안 세므로
항상 큰 각도를 선호한다. 두 축을 같이 보면 J 해는 균일각을 **서포트 1.7배·
왜곡 32% 로 동시에 지배**한다(파레토 우세; 밴드를 4개까지 늘리면 1.9배·38%). 두 밴드 해는 같은 프론티어 위의
다른 점이고, 어디에 설지는 k 가 정한다.

> ⚠⚠ **'서포트 1.7배·1.9배'와 '파레토 우세'는 이후 무효가 됐다** (2026-09-19 절).
> 그 배수는 페리미터 미지지에 섞인 **희소 인필 허상**이 행마다 달라서 생긴 것이다
> (균일 24° 행은 67% 가 허상, 밴드4 행은 28%). 진짜 오버행으로는 균일각이 근소하게
> 낫고, 밴드의 이점은 **같은 오버행을 왜곡 38% 적게** 내는 쪽이다.

### 복잡도 곡선 재작성 (2026-09-08): 밴드 수 N=1~4

`compare_bands.py` — 기존 `compare_complexity.py` 의 '이상적 추정' 대신, 프로필 J 로
각도를 고르고 실제 파이프라인을 돌려 **페리미터 미지지 %** 로 잰다.

**단조성이 점검 기준이다.** N개 밴드는 이웃을 같은 각도로 두면 N−1개를 흉내낼 수
있으므로 J 는 N 에 대해 비감소여야 한다. 처음 돌렸을 때 램프에서 N=2(3.30) >
N=3(2.93) > N=4(2.33) 로 **감소**했고, 이 위반을 따라가 결함 셋을 찾았다.

> ⚠ **이 전제는 이후 좁혀졌다** (2026-09-18 절): 밴드 경계가 `linspace` 라
> 흉내내기는 **n 이 m 을 나눌 때만** 보장된다. 여기서 찾은 결함 셋은 실재했지만,
> 이웃한 N 사이의 감소 자체는 결함의 증거가 아니다.

| 결함 | 증상 | 원인 | 수정 |
|---|---|---|---|
| ① 단일 좌표 이웃 | N=4가 `[24,24,0,0]`(=N=2의 답)에 도달 못 함 | 블렌드 비용은 '이웃 밴드의 각도가 다른 자리'에 붙으므로 한 칸씩 바꾸면 중간 상태가 비용을 다 문다 | 이웃을 **연속한 밴드 덩어리**로 (크기 1 블록을 포함하므로 상위집합) |
| ② 이동 예산이 N에 의존 | N이 커질수록 허리에 못 닿음 | `max_shift = 밴드 높이 × 비율 = h/N` | **모델 높이 기준**으로 (허리까지의 거리는 몇 개로 나눴는지와 무관) |
| ③ 필요 폭을 가용 폭으로 잘라 반환 | 폭 **0.14mm 에 42°→0°**, 층간격 배율 **53.7배**, J=5.72인데 툴패스 5.74% | 자리가 없는 중심이 '폭이 작아 싸다'로 평가되고, `w == avail` 이라 '자리 부족 → 각도 삭감' 검사가 안 걸림 | 진짜 필요 폭을 반환, 자를지는 호출부가 결정 |

추가로 배치 비용을 J 와 정렬했다: `w + |이동거리|` → **`w · r_b`**(블렌드 겉넓이
proxy). J 가 무는 것은 '블렌드 구간의 표면적 × risk' 인데 폭만 보면 "같은 폭이라도
뚱뚱한 높이에서는 표면적이 훨씬 크다"를 놓친다. 이동거리 항은 J 에 대응물이 없는
임의 항이라 동점 처리로 내렸다.

그리고 **안전망**: `select_banded_j` 가 층간격 제약을 어긴 프로필은 J 와 무관하게
탈락시킨다. 계획기에 버그가 있어도 '예측은 최고인데 못 찍는' 해가 뽑히지 않는다.

수정 후 (페리미터 미지지 % / 면적가중 평균 왜곡각):

| N | 구 (허리 없음) | 램프 (허리 있음) |
|---|---|---|
| 1 (균일) | 1.08% / 28.0° | 3.01% / 24.0° |
| 2 | 1.08% / 28.0° | 1.78% / 16.3° |
| 3 | 1.08% / 28.0° | 1.78% / 16.3° |
| 4 | 1.08% / 28.0° | **1.57% / 14.8°** |

- 구는 N 과 무관하게 균일 28° 로 수렴한다 — 블렌드가 비싸 나눌 이유가 없다.
- 램프는 N 이 늘수록 좋아진다(J 증분 +0.963, −0.000, +0.209). N=3 이 N=2 와 같은 값인
  것은 밴드 경계(linspace)가 달라도 전이가 결국 같은 목으로 가기 때문이다.
- ⚠ **J 지형이 평평한 구간이 있다**: 램프 N=2 에서 `[24°,0°]`(J=3.290)와
  `[24°,4°]`(J=3.295)를 0.005 차이로만 구분한다. 툴패스로는 전자가 낫다(1.44% vs 1.78%).
  둘 중 무엇이 뽑히는지는 사실상 임의다.
- ⚠ 툴패스 최소는 `[30°,0°]`(0.83%)인데 J 는 이걸 안 고른다(J=3.121). 결함이 아니라
  **각도 비용 k 가 일한 결과**다 — 툴패스 지표는 서포트만 세고 왜곡(18.6° vs 14.9°)은
  안 센다. 어느 점을 고를지는 k 가 정한다.

### ⚠⚠ 대표 지표가 오버행이 아닌 것을 섞어 세고 있었다 (2026-09-19)

**이 절은 이 문서에서 가장 중요하다. 아래 표들 중 일부의 결론이 뒤집힌다.**

전날 남긴 미해결 건(실제 STL 에서 ①층 "오버행 없음" vs ②층 "페리미터 11.53% 미지지")을
파다가 원인이 나왔고, 그 원인이 **대표 지표 전체**에 걸려 있었다.

#### 원인

검사기 A 는 수평 ≤ 압출폭(0.45mm), 아래로 (0, 층고×1.5] 안에 먼저 퇴적된 점이
있어야 지지로 친다. 그런데 **위로 좁아지는 형상**은 층마다 페리미터가 안쪽으로
들어가 아랫층 페리미터를 그 창 밖으로 벗어나고, 그 자리 아래에는 희소 인필
(간격 2.5mm)밖에 없다. 그러면 미지지로 찍히지만, 물리적으로는 아랫층 **단면
안**이라 몇 mm 건너뛰는 평범한 브리징이다 — 오버행이 아니다.

가장 깨끗한 시연: **위로 좁아지는 순수 원뿔**(아래를 보는 면이 바닥뿐이라 오버행이
정의상 0)에 기존 지표를 대면,

| 원뿔 | 층당 반경 감소 | 기존 '페리미터 미지지' | 진짜 오버행 |
|---|---|---|---|
| r=10, h=20 | 0.20mm (창 안) | 0.00% | 0.00%p |
| r=20, h=10 | 0.80mm | **31.01%** | 0.00%p |
| r=30, h=10 | 1.20mm | **62.77%** | 0.00%p |

오버행이 하나도 없는 형상에서 최대 63% 가 나온다. 판정 창을 넘는 속도로 좁아지기만
하면 생긴다.

#### 고친 것

`conical/toolpath.py` 에 `classify_unsupported` / `support_breakdown` 추가.
미지지 페리미터를 **바로 아래 층의 단면 폴리곤 안/밖**으로 가른다.
안이면 '희소 인필 위'(허상), 밖이면 '진짜 오버행'.

단면은 **페리미터 압출선만으로** 복원한다(`layer_cross_sections`) — 메시 없이
G-code 만으로 되어야 외부 슬라이서 출력에도 쓸 수 있다. 구 모델에서 진짜 단면과
IoU 최소 0.9976. 층은 z 비닝이 아니라 `; layer N` 주석에서 읽는다(원뿔 경로는
역변환 뒤 z 가 층으로 안 나뉜다).

⚠ 한계: 바깥 고리만 채우므로 **부품 내부의 진짜 구멍도 메워진다.** 구멍 위를 지나는
압출이 '단면 안'으로 잘못 분류된다. 실험 모델엔 내부 구멍이 없어 지금은 안 물린다.

#### 세 경로가 같은 답을 준다

1. 메시 단면으로 직접 판정 (수동)
2. G-code 페리미터에서 복원한 단면으로 판정 (`support_breakdown`)
3. **인필을 촘촘히 하기** — 허상이 인필 탓이라면 페리미터 미지지가 진짜 오버행으로
   수렴해야 한다

| 램프 | 인필 2.5mm | 1.2mm | 0.6mm | 진짜 오버행 |
|---|---|---|---|---|

| 밴드4 | 1.57% | 1.41% | **1.20%** | 1.13%p |

정확히 수렴한다. 그리고 **진짜 오버행은 인필 간격과 무관하게 상수**다 — 기하량이니
그래야 하고, 실제로 그렇다. `tests/test_support_breakdown.py` 가 이 성질들을 고정한다.

**살아남는 결론**

- `select_banded_j` 의 선택은 **메시 예측**(①층)으로 하므로 이 허상에 오염되지
  않았다. 계획기는 멀쩡하다 — 오염된 것은 **보고한 수치**다.

**죽는 결론**

- ~~"램프에서 밴드4 가 균일각을 서포트 1.9배로 이긴다"~~ — **틀렸다.** 그 1.9배
  (3.01% vs 1.57%)는 두 행의 허상 비율이 67% 대 28% 로 달라서 생긴 것이다.
  진짜 오버행으로는 균일 24°(1.01%p)가 밴드4(1.13%p)보다 **근소하게 낫다.**
- ~~"밴드가 균일각을 두 축에서 동시에 지배한다(파레토 우세)"~~ — **틀렸다.**
  파레토 우세가 아니라 **트레이드오프**다: 오버행 +12% 를 내주고 왜곡 −38%
  (24.0° → 14.8°)를 얻는다.

**바뀐 주장 (그날 오후 한 번 더 바뀌었다 — 아래 k_blend 절)**

> 밴드는 균일 원뿔을 오버행에서 이기지 않는다. **거의 같은 오버행을 훨씬 적은
> 왜곡으로** 달성한다.

⚠ **이 문장은 `k_blend=0.5` 에서만 맞았다.** 그 기본값이 과했던 것이 곧 드러났고
(아래 'k_blend 재보정' 절), 0.1 로 낮추면 램프에서 J 해가 **0.33%p / 18.6°** 를
찾아 균일각(1.01%p / 24.0°)을 **두 축 모두에서 지배**한다. 즉 원래의 '파레토
우세' 주장은 사실이었고, 오염된 지표와 과한 k_blend 가 그걸 가리고 있었다.
배수만 달라진다 — 옛 지표로 1.9배가 아니라 진짜 오버행으로 3.1배다.

#### k_blend 재보정 (같은 날): 0.5 → 0.1

지표를 고치자 **그 지표로 정해졌던 상수**가 틀린 것으로 드러났다.

`k_blend` 는 "구에서 밴드가 균일각에 진다(4.93% vs 1.08%)"를 고치려고 넣은
항이다. 그런데 그 4.93% 중 **4.45%p 가 오버행이 아니었다** — 진짜 오버행은
0.48%p 로 균일(0.51%p)보다 오히려 낫다. 즉 이 항이 필요해 보이게 만든 근거가
허상이었다. 기본값 0.5 도 `analyze_blend_k.py` 가 낸 창(0.1~1.5)의 한가운데를
택한 것인데, 그 창의 '정답'("구=균일, 램프=부위별")이 같은 허상으로 정의돼 있었다.

진짜 오버행으로 k_blend 를 훑었다:

| 모델 | k_blend | 진짜 오버행 | ⟨\|θ\|⟩ | 고른 각도 |
|---|---|---|---|---|
| 구 | 균일 28° (기준) | 0.51%p | 28.0° | — |
| 구 | 0.0 | 1.81%p | 16.2° | [36, −44] 블렌드 19.9mm ← 병리적 |
| 구 | 0.1 / 0.5 / 1.5 | 0.51%p | 28.0° | 균일로 수렴 |
| 램프 | 균일 24° (기준) | 1.01%p | 24.0° | — |
| 램프 | 0.0 | 0.33%p | 18.6° | [30, 0] |
| 램프 | **0.1** | **0.33%p** | **18.6°** | [30, 0] |
| 램프 | 0.5 (옛 기본값) | 1.12%p | 16.3° | [24, 4] |
| 램프 | 1.5 | 1.05%p | 21.7° | [24, 18] |

**0.1 로 낮췄다.** 램프에서 3.4배 낫고(1.12 → 0.33%p) 구에서는 동일하다 —
잃는 것 없이 얻는다. 0 으로 두면 여전히 병리적이라(구에서 방향을 뒤집어
블렌드 19.9mm) 항 자체는 남긴다.

**그래서 원래 주장이 되살아난다.** k_blend=0.1 에서 램프의 J 해는
**0.33%p / 18.6°** 이고, 균일각(1.01%p / 24.0°)을 **두 축 모두에서 지배**한다
(오버행 3.1배, 왜곡 −22%). 이 연구가 처음에 주장했던 파레토 우세는 사실이었다.
오염된 지표와 과한 k_blend 가 동시에 그것을 가리고 있었고, 지표를 고치니
상수도 따라 고쳐졌다.

⚠ **남은 열린 질문**: 선택에 블렌드 비용을 아예 안 넣는 `select_banded` 가
구에서 **0.48%p / 18.9°** 로 균일(0.51%p / 28.0°)을 두 축 모두에서 약간 이긴다.
지금 J 는 어떤 k_blend 에서도 그 해를 못 고른다(전부 균일로 수렴). "구에서는
균일이 정답"이라는 전제를 다시 봐야 한다 — `analyze_blend_k.py` 의 창 분석을
진짜 오버행으로 다시 돌리는 것이 다음 순서다.

#### 왜 이게 지금 중요한가 — 첫 실물 실험의 설계가 여기서 나온다

다음 달 실물 프린터가 나온다. 실물 실험의 질문은 '예측대로 나오나'가 아니라
**'어느 지표가 실물과 맞나'** 여야 한다. 두 지표가 **순위를 반대로 매기는**
케이스를 뽑으면 한 번의 출력으로 판정되기 때문이다.

**판정 모델: 구, `균일 28°` vs `밴드2(층간격 제약, select_banded)`**

| 전략 | 옛 지표 (페리미터 미지지) | 진짜 오버행 | ⟨\|θ\|⟩ |
|---|---|---|---|
| 균일 28° | **1.08%** (좋음) | 0.51%p | 28.0° |
| 밴드2 (제약) | **4.93%** (나쁨, 4.6배) | **0.48%p** (좋음) | 18.9° |

옛 지표는 균일이 4.6배 낫다 하고, 진짜 오버행은 밴드가 (근소하게) 낫다 한다.
**둘 다 맞을 수는 없다.** 같은 모델을 두 전략으로 뽑아 표면을 보면 끝난다 —
밴드 쪽 표면이 눈에 띄게 나쁘면 옛 지표가 뭔가 실재하는 것을 보고 있었다는
뜻이고(희소 인필 위 브리징이 실제로 표면을 상하게 한다), 차이가 없거나 밴드가
나으면 새 지표가 맞다.

⚠ 램프는 판정 모델이 **아니다.** `k_blend=0.1` 로 바꾼 뒤에는 두 지표가 램프에서
같은 순위를 준다(둘 다 밴드 승). 처음엔 램프를 판정 모델로 잡았는데, 상수를
고치면서 그 성질이 사라졌다 — 판정 실험을 설계할 때는 **그 시점의 수치로 다시
확인**해야 한다.

### 표본 7개 재측정 (2026-09-19): 고친 지표 + k_blend=0.1

전날(2026-09-18) 스윕은 **오염된 지표와 옛 상수**로 낸 것이다. 둘 다 고친 뒤
같은 표본으로 다시 돌렸다. `compare_bands.py --waist-sweep --n-max 6` + 실제 STL.

| 모델 | 허리 | 균일 N=1 | 밴드2 (실제 기본) | 배수 | 오버행 최소 |
|---|---|---|---|---|---|
| 구 | 0.00 | 0.51%p / 28.0° | 0.51%p / 28.0° | ×1.0 | N=1 0.51%p |
| 허리 r=7 | 0.00 | 0.90%p / 18.0° | 1.00%p / 8.6° | ×0.9 | N=1 0.90%p |
| 허리 r=5 | 0.29 | 0.96%p / 20.0° | 1.06%p / 11.2° | ×0.9 | N=4 0.92%p |

**① 허리 문턱이 선명해졌다.** 두드러짐 ≤0.29 에서는 이득이 없고(×0.9~1.0),
≥0.57 에서는 3.1~4.1배다. 문턱은 0.29 와 0.57 사이 어딘가다.

전날 J 기준으로는 이 경계가 안 보였다 — "0.5 아래는 부호가 뒤섞여 경향이라
부를 수 없다"고 적었다. 축을 진짜 오버행으로 바꾸니 경계가 드러났다. **J 이득은
허리와 거의 무관하게 1.7~2.1 로 평평하다** (J 는 왜곡 감소도 같이 세기 때문).
묻는 질문이 '허리가 있어야 오버행을 줄이나' 라면 축도 오버행이어야 한다.

**② 밴드 수 N 을 J 로 고르면 안 된다** — 볼트 TODO 의 미결 항목에 대한 답이다.

| 모델 | J 최대 N | 그때 오버행 | 달성 가능한 최소 |
|---|---|---|---|
| 구 | N=5 | 1.84%p | N=1 0.51%p |
| 허리 r=3 | N=6 | 1.39%p | N=2 0.32%p |
| 허리 r=1 | N=6 | 2.36%p | N=3 0.24%p |

7개 중 **6개**에서 J 최대 N 의 오버행이 최소보다 나쁘다. 이유는 결함이 아니라
구조다: J 는 경계가 겹치는 짝에서 N 에 대해 비감소이므로 N 을 J 로 고르면 항상
커지는 쪽으로 가고, J 는 각도 비용 k 때문에 '밴드 많고 각도 낮은' 해를 선호한다.
N 은 지금처럼 사람이 준다(`--auto-bands N`). 자동화하려면 **N 자체에 대한 비용**이
따로 필요하다.

**③ 높은 N 에서 병리적 해가 남아 있다.** 허리 r=5 의 N=6 이 `[24,14,4,−34,0,0]` —
중간에 −34° 로 **방향을 뒤집는다**. 오버행 1.58%p 로 N=4(0.92%p)보다 나쁜데 J 는
더 높다. k_blend=0.1 이 구의 방향 전환은 막았지만 모든 경우를 막지는 못한다.

⚠ 전날 절(아래)의 수치는 **옛 지표·옛 상수**다. 단조성 점검·경계 겹침에 대한
논의는 그대로 유효하지만, 오버행 수치는 이 절을 본다.

#### ⚠ 단조성 점검의 전제가 틀렸다 (측정 쪽 결함)

허리 r=7 에서 J 가 N=3(1.28) → N=4(1.14) 로 **감소**했다. 이 레포에서 단조성
위반은 지금까지 전부 진짜 계획기 결함이었으므로 같은 식으로 쫓았는데, 이번엔
원인이 계획기가 아니라 **점검의 전제**였다.

전제는 "N개 밴드는 이웃을 같은 각도로 두면 N−1개를 흉내낼 수 있다" 였다. 그런데
밴드 경계가 `linspace` 라 N=3 의 경계(33.3%, 66.7%)는 N=4 의 경계(25%, 50%, 75%)에
**하나도 들어 있지 않다.** N=4 는 66.7% 에 전이를 놓을 수 없으므로 N=3 의 해를
원리적으로 흉내낼 수 없다.

실측으로 확인:

- N=3 의 해 `[18,18,16]` → J = **1.2826**
- 같은 해를 N=6 으로 흉내내면(경계가 겹친다) `[18,18,18,18,16,16]` → J = **1.2826**,
  차이 **0.00e+00**
- N=4 에서 '한 번만 꺾는' 해를 **전수 조사**해도 최대 **1.1356** — 좌표하강이 찾은
  값과 같다. 즉 탐색이 못 찾은 게 아니라 격자에 그 해가 **없다**.

그래서 점검을 고쳤다: 흉내내기가 보장되는 짝은 **n 이 m 을 나눌 때뿐**이고
(1→2, 2→4, 3→6 …), 그 짝에서의 감소만 결함으로 부른다. 이웃한 N 사이의 감소는
격자 비정합이므로 참고로만 찍는다. 고친 점검으로 일곱 모델 × 겹치는 짝 8개가
전부 비감소다. `tests/test_band_nesting.py` 가 이 성질 셋을 고정한다.

이건 계획기가 아니라 **측정 도구의 결함**이었다. 헛경보는 없는 버그를 쫓게
만들고, 같은 이유로 진짜 결함도 가린다.

#### 허리 두드러짐 지표

```
prominence = max over interior z*  of  1 − r(z*) / min(max r below, max r above)
```

위쪽 최대를 기준에 넣는 것이 핵심이다. `min(r)/max(r)` 로 재면 위로 갈수록
가늘어지기만 하는 형상(구·원뿔·깔때기)의 꼭대기 테이퍼가 '깊은 허리'로 잡힌다 —
거기는 위에 아무것도 없어서 각도를 바꿔도 얻을 게 없는데도 그렇다.
`tests/test_waist_prominence.py` 가 구·원뿔 = 0, r_neck 축에서 단조증가,
예측값 1 − r_neck/7 과 일치를 고정한다.

⚠ 축대칭을 가정한 반경 프로필 위에서 잰다. 축비대칭 모델에서는 대표성이 떨어진다
(블렌드 폭 공식이 같은 근사를 쓰므로 **계획기와 같은 기준**이라는 점은 맞다).
