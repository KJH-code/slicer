## 1. 무엇을 말하는 보고서인가

### 한 줄 주장
> 곡면 슬라이싱은 변수가 너무 많아 다루기 어렵고, 원뿔 슬라이싱은 변수가 적지만 효율적이다.
> 그런데 원뿔각을 자동으로 정하는 방법이 없었다. 그래서 그 알고리즘을 만들었고,
> **그 결정을 믿을 수 있는지** 해석식부터 실물까지 단계별로 검증했다.

### 지금 초안의 문제
- 요약문과 초록에 결과 ①~⑥이 같은 무게로 나열돼 있어서 중심이 보이지 않는다
- RQ1 안에 1.1~1.8 이 몰려 있다. 실물 출력(IV.4)과 계산 비용(IV.5)은 따로 떨어져 있다
- 사전 등록 기준 T1 불통과가 '실패'로 읽힌다

## 2. 장별 구성

### I. 서론 (밴드 없이, 짧게)
1. 곡면 슬라이서(S³-Slicer, Neural Slicer, S4)는 딥러닝을 쓰거나 위치마다 방향을 정해야 해서 변수를 다 통제하기 어렵다
2. 원뿔 슬라이싱은 변수가 θ 하나라 계산이 가볍고, 방사 대칭 형상에 효율적이며, 기존 평면 슬라이서를 그대로 쓸 수 있다(Table 1)
3. 그런데 θ 는 지금까지 사용자가 정해 왔다 → **원뿔각을 자동으로 정하는 알고리즘이 필요하다**
4. 연구 질문은 두 개를 제시한다. **RQ1** 원뿔각을 형상에서 자동으로 정할 수 있는가. **RQ2** 그 결정을 믿을 수 있는가

### II. 이론적 배경
지금 내용(원뿔 변환, 판정식, 가변각 층간격, 압출 보정)을 유지한다. 추가할 것은 하나다.
- 판정식(2) 앞에 **"왜 변환 공간이 아니라 원본 법선으로 판정하는가"**를 한 문장으로 둔다
  (funnel 벽: 원본 26° 대 변환 공간 50.7°). 그래야 III 장으로 자연스럽게 이어진다

### III. 연구 방법
1. **알고리즘** — J = ΔS − k|θ|
   - **"왜 1차인가"** 문단을 새로 넣는다. 위치는 k 의 의미 설명 바로 앞(J 의 형태 → 계수 k 순서)
   - 근거: 18개 모델, 2구간 4° 격자(144조합) 툴패스 실측. 후회 중앙값은 1차 0.004%p, 2차 0.074,
     3차 0.117, 4차 0.190. 1차는 18개 모두에서 최저이거나 공동 최저였다. 기본 선택기에 고차 항을 더한
     216회 실행에서 오버행이 줄어든 경우는 0회였다
   - 출처: `wjd` 저장소 `claude/tender-shannon-9d6kk2` 브랜치, 커밋 `ca668cd`(`analyze_theta_power_more.py`)
2. **검증 계층**(Table 3) — 해석식 → 툴패스 → 퇴적 복원 → 기계 사전 검사 → 실물
3. **실험 조건**(Table 4) — **차수 비교 표본 18개**를 한 줄 추가한다(기본 표본 21개와 다른 집합이다)

### V. 고찰
지금 항목을 유지하되 결과 순서에 맞춰 다시 배열한다.
1. 각도 비용과 k(T1 → k 분리, 층고에 따른 k 차이)
2. 고정 임계각 45° 의 한계(funnel, 실측 처짐 시작 각도와 비교)
3. 구간 분할의 고유 효과와 블렌드 비용
4. 실물 예측의 불일치(L4 압출 모형, L5 처짐 각도)
5. 견고성

### VI. 결론
결과 순서대로 요약하고, **마지막 문장은 신뢰도**로 끝낸다.
예: "해석식의 판단은 G-code·실물과 일치했고 교란에도 J 손실이 작아, 자동 결정을 믿고 쓸 수 있는 근거를 얻었다."

## 3. 하드웨어: 3축 대 5축 실물 실험

자세한 설계는 `hardware_comparison_plan.md` 에 있다. 보고서에는 IV.4.6 에 들어간다.

| 비교 | 바꾸는 것 | 답하는 질문 |
|---|---|---|
| C1 기계 기준선 | 3축 ↔ 5축 (둘 다 평면) | 개조한 5축이 평면 출력 품질을 해치지 않는가 |
| C2 노즐 기울기 | 노즐 수직 ↔ 노즐 기울임 (같은 원뿔 층) | 같은 층을 5축으로 뽑으면 무엇이 나아지는가 |
| C3 각도 결정 | 균일 ↔ 밴드 (5축, 램프, 층고 0.3/0.4) | 알고리즘의 판정이 실물과 맞는가 |

출력은 12개(3축 5개, 5축 7개)이고, C1 → C2 → C3 순서로 진행한다. 판정 기준은 출력 전에 커밋한다.

### 먼저 고칠 데이터 문제
- RE.zip 의 '5축' G-code 에는 **회전축 이동이 없다**(Bambu Lab X2D 용 평면 G-code). 우리 파이프라인으로 다시 뽑아야 한다
- 3axis 폴더의 L 번호가 한 칸씩 밀려 있고, 원기둥(L1) 화면이 없으며, L5 는 L4 와 같은 파일이다
- Table 11 의 실측값은 이전 세션의 시뮬레이션 결과와 숫자가 같다. 팀은 실제로 측정했다고 확인했다.
