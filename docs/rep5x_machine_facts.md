## 2. 역기구학 (펌웨어가 계산)

```
Xj = X − sinC·LC + cosC·sinB·LB
Yj = Y + (cosC−1)·LC + sinC·sinB·LB
Zj = Z + (cosB−1)·LB
```
출처: M `Marlin/src/module/penta_axis_head_head.cpp:129-135` [S]. 공구축(팁→몸체) = `(sinB·cosC, sinB·sinC, cosB)` [I].

| 상수 | 값 | 근거 |
|---|---|---|
| LC, LB (예제 config) | 1.6, 54.67 | EX:1218, 1221 [S] |
| LC, LB (Firmware Builder 기본값) | 2.30, 52.87 | K `tools/firmware-builder/js/app.js` [S] |
| LC, LB (빌드 가이드 참고 config) | 0.0, 47.9 | K build-guide [S] |
| **우리 기계** | **[실기] `M665` 로 읽을 것** | 세 출처가 서로 다르다 |

→ 우리 G-code는 **LB에 의존하지 않는다** (팁 좌표 + B/C만 내고, IK는 펌웨어가 한다). LB는 점검(joint Z, 베드 간섭)에서만 쓴다.

## 8. 핫엔드

- 순정 Sprite는 Bowden 고정부가 없어서 Bowden 호환 핫엔드로 바꾸거나 개조한다. 외장 Bowden 익스트루더 + 약 500mm PTFE. 모델명은 문서에 없다 (K `bom-e3v3se.md`) [D]
- 공식 수치는 G-code Viewer의 충돌 모델뿐이다 (K `tools/gcode-viewer/js/printheads/ender3-v3-se.js:14-29`). 팁이 원점이고 높이는 공구축 방향 [S]:
  - 노즐: 반경 4.5mm 원통, 높이 2~8mm
  - 히트블록: 24×20×24mm 박스, 높이 8~28mm, 옆으로 +2mm 편심
  - 히터 케이블: 반경 3mm, 옆 −15mm, 높이 18mm
- 이 모델로 팁이 베드면에 있을 때 닿기 시작하는 각도: 노즐 몸통 약 24°, 블록 모서리 약 30~39° [I]
- **[실기] 캘리퍼스로 실측**할 것. 교체 핫엔드라면 위 모델은 맞지 않는다

## 9. 공식 G-code 관례 (Vase Generator)

- 형식 `G1 X Y Z C B E F`, 팁 좌표, 원점 베드 중앙, M83(상대 E), 기본 20mm/s [S]
- 임의 모델의 5축 슬라이싱은 "외부 도구"라고 논문 §5.3이 명시한다. 이 저장소가 채우는 자리다 [D]

## 10. 두 가지 실행 경로

| 경로 | 어떻게 | 제약 |
|---|---|---|
| 라이브 TCP | `G43.4` 켜고 팁 좌표를 그대로 보냄 | 조밀한 경로에서 플래너가 굶어 **끊김(stutter)** 이 생길 수 있다 (논문 §5.2) [D] |
| SD 전처리 | `M668` → 펌웨어가 SD 파일을 joint 좌표로 미리 변환 | **SD 인쇄 전용** (USB 스트리밍이면 실패한 채 G49 상태로 팁 좌표가 joint로 실행됨). 이동 줄은 **0열 `G`로 시작, 127자 이하, 주석 금지** (주석 속 `z0.6`도 Z로 읽힘). 회전은 5° 단위로 분할. G2/G3 미지원 [S] |

우리 G-code는 **둘 다 되는 형식**으로 낸다: 이동 줄은 0열 `G`, 주석 없음, 127자 이하.

**M668 소스 확인 (2026-11-10, M `Marlin/src/sd/ik_preprocessor.cpp`, `Marlin/src/gcode/sd/M668.cpp`)** [S]:

- M668은 **그 줄 다음부터** 파일 끝까지를 `_iktmp.gco`로 변환해 출력한다. 앞에 `G49`를 넣고 `G43.4`/`G49` 줄은 버린다. 그래서 출력 내내 TCP가 꺼져 있다
- M82/M83을 추적한다. 절대 E도 된다. `G92 X Y Z C B E`도 추적한다. `G28`은 추적값을 0으로 초기화한다 (실제 홈 자세와 다르다. 그래서 G28 직후 회전 이동에는 X Y Z C B를 다 적는다)
- 회전 변화가 5°를 넘는 이동만 5° 조각으로 나눈다. 회전이 없는 이동(추적 C·B가 0)은 그대로 지나간다
- joint 좌표로 실행되므로 **소프트 엔드스톱이 joint에 걸린다.** 기울이면 joint Z가 음수가 되므로 공식 흐름은 `M211 S0`이다. `rep5x_check.py`는 M668 + 엔드스톱 켬 + joint Z<0을 치명으로 잡는다
- F는 joint 경로 길이에 걸린다 [I]. 축 근처에서는 헤드가 LB·sinB 반경으로 돌아 팁 속도가 느려진다
- 우리 기본 프로파일(`rep5x_ender3v3se.ini`)은 M668을 쓰지 않는다 (라이브 TCP, 엔드스톱 켬). 끊김이 보일 때 쓸 판은 `rep5x_ender3v3se_m668.ini`

## 11. 첫 출력 위험 (소스에서 나온 것)

1. 보호 장치가 없다. `M211 S0`, 프로브 없음, Z-min 스위치 없음. G-code가 틀리면 그대로 충돌한다
2. B 홈이 −135°다. 호밍 뒤 `G0 B0 C0` 없이 출력하면 기운 채로 시작한다
3. TCP 전환은 B0 C0에서만
4. 회전 큰 짧은 이동은 축 한계까지 간다 → F 상한 필요
5. 보정 전 오차가 크다 (논문 §6.1: B=90°에서 약 5mm, 전 범위 2.85mm RMS, 보정 후 0.15mm RMS) [D]
6. `DISABLE_IDLE_Z` 120초. 끝나고 Z가 헤드 무게로 흘러내릴 수 있다 [I]
7. 다른 빌더들이 보고한 것: Bowden 강성, 연속 회전 시 Bowden 꼬임, heat creep (논문 §6.5) [D]
