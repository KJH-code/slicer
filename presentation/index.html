01 · 지난 발표 이후

지난 발표가 남긴 문제와, 그 뒤 해결한 것

영역지난 발표에서 남은 과제현재
형상·각도 분석선택 각도를 평가할 기준이 없었다완료 — 툴패스 실측을 지표로 확정
공간 분할구간 경계·전환 규칙 미검증완료 — 블렌드 폭 닫힌 식, 경계 자동 이동
경로·시각화구간별 G-code 생성 형식 미통합완료 — θ(Z′) 단일 파이프라인
물리·운동학축 제약·충돌을 각도 평가에 반영일부 — 3축 노즐 간섭 검사기까지
실험 검증실제 출력 데이터 확보미해결 — 이번 발표의 주제

가장 컸던 문제 세 가지

  1. 판정 기준이 두 개였다

    왜곡공간에서 45°로 재는 방식과 해석식이 서로 반대 결론을 냈다. 원뿔 변환은 등각이 아니므로 왜곡공간 각도는 물리 각도가 아니다 — 해석식으로 통일하고 옛 결론은 철회했다.

  2. 예측을 검증할 수단이 없었다

    메시 예측만 있고 독립 지표가 없었다. 예측이 “서포트 0.5%”라던 프로필을 나중에 툴패스 검사기가 미지지 25.5%로 잡아냈다.

  3. 비교 대상을 잘못 잡고 있었다

    “평면 대비 감소”는 원뿔 슬라이싱의 성과이지 우리 것이 아니다. 넘어야 할 선은 균일 원뿔(RotBot식 고정각)이라고 다시 정의했다.

상반기에 고친 것은 대부분 ‘무엇으로 판정하는가’였다. 남은 하나가 물리 검증이고, 그것이 이번 발표의 출발점이다.

02 · 검증용 코드 설계

하드웨어 없이 “맞다”를 세우는 검증 계층 설계

①

단위 테스트 12종

수식 구현의 자기 일관성. 상수 프로필 = 고정각임을 회귀로 강제.

보증 못 함: 수식이 물리적으로 맞는지
②

툴패스 가상 검사기 A·B

예측과 측정 대상이 다른 독립 지표. A는 압출 세그먼트를 점 샘플링해 지지 여부를, B는 노즐·히트블록 기하로 간섭을 본다.

보증 못 함: 검사기와 예측기가 같은 가정으로 함께 틀릴 가능성
③

브라우저 독립 재구현

문서 수식만 보고 JS로 다시 짠 구현이 Python과 점 단위 일치 — 26,727점 100.0000%.

보증 못 함: 둘 다 같은 AI 도구로 작성 — 완전 독립 아님
④

사람 손계산

점 하나를 클릭하면 숫자가 대입된 식이 나오고 계산기로 따라칠 수 있다. AI를 거치지 않는 유일한 경로.

보증 못 함: 전수 검사가 아님
⑤

팀원 독립 구현 대조

같은 수식을 다른 사람이 따로 구현한 코드와 약 22,000면 대조 — 임계각 최대 차이 1.42×10⁻¹⁴°, 도달 불가 면 집합까지 일치.

보증 못 함: 두 사람이 같은 오해를 했을 가능성

②층이 실제로 일했다

설계 원칙

각 층이 보증하지 못하는 것을 같이 적는다. 안 적으면 층을 쌓은 게 아니라 테스트를 많이 짠 것일 뿐이다.

03 · 다중 모델 검증

여러 형상에서 원뿔각 선택을 검증하다 — 조건을 찾았다

검증한 형상

구 · 램프 · funnel 세 모델 × outward/inward 두 방향, 그리고 각 모델에서 원뿔각 0°~44°를 스윕했다.

결론은 조건부다

부위별 각도가 균일 원뿔을 이기려면 모델에 ‘허리’가 있어야 한다. 각도를 바꾸려면 전이 구간이 필요하고 그 폭은 그 높이의 반경에 비례하기 때문이다. 구는 어디나 뚱뚱해 전이가 모델 높이의 73%를 먹는다.

임계 규칙도 눈금 문제였다

팀 안의 두 κ 규칙(고정 45° vs 형상 의존)을 토론 대신 실측 순위상관으로 판정했다. κmax≈0.85에서 두 규칙이 만나고(ρ=+0.943), 1.0에서는 형상 의존 쪽이 오히려 낫다(+0.986).

안전판

균일각 후보를 전수 평가해 탐색에 섞었다. 그래서 결과가 최선 균일 원뿔보다 나쁠 수 없다는 성질이 구조적으로 보장되고, 회귀 테스트로 강제된다.

04 · 통합 파이프라인

STL 한 개를 넣으면 G-code까지 — 통합 파이프라인 완성

  1. 01

    축 센터링

    XY 바운딩박스 중심을 0으로, 바닥을 z=0으로. 축 밖 모델은 변환이 균일 이동으로 수렴해 각도가 무의미해진다.

  2. 02

    각도 결정

    해석식 g(θ)=nzcosθ + d·nrsinθ 로 서포트를 예측하고, 평가함수 J로 균일·밴드 후보를 고른다.

  3. 03

    정변환(왜곡)

    θ(Z′)를 tanθ의 조각별 선형으로 두면 정변환이 이분법 없이 정확해로 풀린다.

  4. 04

    평면 슬라이싱

    PrusaSlicer CLI를 감싼다. 서포트·arc fitting·자동배치를 끄고 절대 E로 고정한 프리셋을 못박았다.

  5. 05

    역변환

    직선이 곡선이 되므로 허용 현오차 ε에서 L=2√(2rε) 로 적응 분할한다. 고정 분할은 100만 줄을 만들었다.

  6. 06

    G-code 출력

    ;CONICAL_META 자기기술 헤더와 ;TYPE: 압출 종류 태그를 함께 내보낸다.

  7. 07

    검사·시각화

    툴패스 검사기와 브라우저 시뮬레이터가 같은 G-code를 읽어 독립적으로 평가한다.

재발명하지 않은 것

슬라이서를 새로 짜지 않는다. 왜곡한 STL을 외부 슬라이서에 넘기고 결과를 역변환한다 — 우리가 만드는 것은 앞뒤(각도 결정·왜곡·역변환)뿐이다.

튜닝 값은 한 곳에

임계각·최대각·탐색 간격·k·kblend·층간격 상한이 전부 config.py에 있고 주석에 근거가 달려 있다.

가중치는 ‘창’으로 정한다

값을 찍는 대신 답이 바뀌는 구간을 측정했다. kblend는 두 모델의 정답을 동시에 맞히는 구간이 0.1~1.0이고 기본값 0.5는 그 안이다.

일곱 단계 각각이 한 번씩 실제로 터진 뒤에 지금 모양이 되었다. 파이프라인 설계는 그 실패 목록이기도 하다.

05 · 이번 단계의 핵심

남은 한 층은 실물이다 — 이번 핵심은 3D 프린터 설계

지난 발표까지

“실물 출력은 범위 밖”

장비·여건상 실물 출력이 불가능하다고 판단해 검증 계층의 마지막 자리를 독립 구현 대조로 대체했다. 그래서 모든 결론을 ‘증명’이 아니라 ‘경향’으로만 썼다.

  • 브리징·수축·층간 접착은 끝내 검증되지 않는다
  • 노즐 간섭 검사기는 3축 가정에 머물러 있다
  • 5축 모드(open5x.py)는 돌릴 기계가 없어 [실험적] 딱지를 못 뗀다

이번 단계

기성 프린터를 5축으로 개조한다

5축 프린터를 처음부터 설계하는 것은 이 연구의 범위를 넘는다. 슬라이서를 재발명하지 않았던 것과 같은 이유로, 프린터도 재발명하지 않는다.

오픈소스 5축 레트로핏 Rep5x(GPL v3)를 기반으로, 보유 기종인 Ender 3 V3 SE용 개조를 설계·제작한다.

  • CAD·BOM·펌웨어·조립 문서가 전부 공개되어 있다
  • 개조 부품 대부분을 기존 3D 프린터로 직접 출력할 수 있다
  • 연속 회전(C)과 >90° 틸트(B) — 원뿔 슬라이싱에 필요한 자유도를 그대로 준다

왜 이것이 알고리즘 연구의 일부인가

①

검사기와 예측기가 같은 가정으로 함께 틀릴 가능성은 시뮬레이션 안에서는 원리적으로 못 지운다. 실물만이 다른 종류의 증거다.

②

지금의 지표는 기하학적 지지다. 층간 접착·브리징 품질은 재료 물성이라 출력 없이 값이 생기지 않는다.

③

기계가 정해져야 MAX_ANGLE·충돌 기하·축 속도 한계가 실제 숫자가 된다. 지금은 전부 가정값이다.

우리가 만들 기계 — Ender 3 V3 SE + Rep5x 5축 헤드

설계 구성

  • C축(요)Z축 둘레 연속 회전. 슬립링(12채널·2A)이 배선 꼬임을 없앤다.

    07 · 코드 연결

    기계가 정해지자 코드가 달라졌다 — 5축 출력 경로 설계

    기존 구현 · conical/open5x.py

    Open5x — 베드가 움직인다

    노즐은 수직 고정. 베드를 U로 기울이고 V로 돌려 압출점의 레이어면을 수평으로 만든다.

    • 펌웨어가 회전 기구학을 하지 않는다(M669 K0 항등) → 슬라이서가 기계좌표를 직접 계산
    • V가 한 방향으로 계속 누적 — 구 데모 기준 약 149회전, 배선 감김 대책 필수
    • 축 근처 트래블에서 V가 한 이동에 ±180° 급회전
    • 피벗 깊이·부호는 문서에 없어 실기 보정 필요
    설계 중 · conical/rep5x.py

    Rep5x — 헤드가 회전한다

    베드는 고정. 노즐 자체를 B(틸트)·C(요)로 돌려 원뿔 레이어 법선에 맞춘다.

    • Marlin이 PENTA_AXIS_HH 역기구학을 펌웨어에서 수행 → 슬라이서는 노즐 끝 좌표 + 각도만 내면 된다
    • G43.4로 IK 켜고 G49로 끈다. 피벗 보정은 M424 Y<LC> Z<LB> (기본 LB=47.9 mm)
    • 슬립링이 있어 C 연속 누적이 배선 문제를 일으키지 않는다 — Open5x의 최대 난점이 사라진다
    • 기계 한계가 가정값이 아닌 실제 값이 된다: B ±135°, C ±360°

    원뿔 레이어 → 5축 명령 대응

    outward 원뿔 레이어의 국소 법선은 n̂ = sinθ·r̂(φ) + cosθ·ẑ. 노즐 축을 n̂에 맞추면 두 각이 바로 떨어진다.

    # 부품좌표 (x, y, z) 와 그 높이의 원뿔각 θ(z) 로부터
phi = degrees(atan2(y, x))        # 압출점의 방위각
B   = theta_at(z)                 # 틸트 = 그 높이의 원뿔각
C   = unwrap(phi, C_prev)         # 요 = 방위각, 연속 누적 (슬립링)

# 노즐 끝 좌표를 그대로 쓴다 — TCP 보정은 G43.4 가 펌웨어에서 처리
emit(f"G1 X{x:.3f} Y{y:.3f} Z{z:.3f} "
     f"B{B:.3f} C{C:.3f} E{e:.5f} F{f_adj:.0f}")
    • 가변각이 그대로 실린다. θ(z)가 변하면 B도 층마다 변한다 — 우리 프로필 파이프라인이 이미 만드는 값이다.
    • 피드레이트 재조정은 남는다. 회전축이 이송 norm에 어떻게 들어가는지는 기계에서 재야 한다.
    • 부호는 실기 보정 대상. B의 양의 방향과 C의 0점은 조립 결과에 달려 있다.

    08 · 현재까지의 문제점

    지금 남아 있는 문제 — 알고리즘·기계·검증

    01

    물리 검증은 아직 0건

    조립 전이므로 브리징·수축·층간 접착은 여전히 미검증이다. 모든 결론은 지금도 ‘증명’이 아니라 경향으로만 쓴다.

    02

    Rep5x 기구학 모듈 미구현

    open5x.py는 베드 틸트 전제라 재사용할 수 없다. 헤드 회전용 rep5x.py는 설계만 되어 있고 검증 테스트가 없다.

    03

    노즐 간섭 검사기가 3축 가정

    검사기 B는 노즐이 수직이라고 가정한다. 헤드가 기울면 히트블록·B암 전체가 충돌 기하에 들어와야 한다.

    04

    가변각 × 5축이 미결

    고정각이면 B가 상수라 단순하지만, θ(z)가 변하면 B도 계속 변한다. 현재 가변각은 3축 소각도 모드에서만 지원된다.

    05

    모델 표본이 두 개

    kblend 창도 κmax 결론도 구·램프 두 모델로 정한 값이다. 표본이 늘면 재검토 대상이라고 코드에 적어 두었다.

    06

    블렌드 비용이 휴리스틱

    J의 (m−1)/(limit−1) 선형 가중은 유도된 물리가 아니다. 근거를 더 세우거나 실측으로 형태를 정해야 한다.

    07

    기종 개조에 딸린 제약

    V3 SE는 스톡 핫엔드가 보우덴 비호환이고 순정 스크린이 Marlin에서 동작하지 않는다. 부품 조달과 개조 시간(24~34h)이 일정 위험이다.

    08

    기계 파라미터가 전부 미측정

    LC/LB 피벗 오프셋, 축 원점, 최대 안전 원뿔각, 축 속도 한계 — 지금은 문서 기본값뿐이고 실기 캘리브레이션이 있어야 값이 생긴다.

    실물 출력 비교

    평면 · 균일 원뿔 · 밴드 세 조건을 같은 모델로

    1순위

    예측 → 검사기 → 실측 3단 대조

    지금까지 예측과 툴패스 검사기의 순위상관(ρ=1.00)까지만 확인했다. 같은 모델을 실제로 출력해 서포트 필요 면적·표면 품질·실패 구간을 재면, 검사기가 예측기와 함께 틀리고 있었는지를 처음으로 밖에서 확인할 수 있다.

    2순위

    5축 충돌·안전각을 실제 기하로

    B암과 핫엔드의 실제 치수로 충돌 검사기를 다시 쓰고, find_max_safe_angle.py가 내는 MAX_ANGLE을 이 기계의 값으로 바꾼다.

    3순위

    모델 표본 확대

    허리 있는 형상·없는 형상을 더 모아 kblend와 κmax 창을 다시 잰다. 두 모델로 정한 상수라는 한계를 표본으로 지운다.

    지키는 것

    정직성 규약은 그대로

    실물이 생겨도 ①결과는 경향, ②선행연구의 것을 우리 것이라 하지 않는다, ③학생이 설명 못 하는 코드는 넣지 않는다 — 세 줄은 유지한다.
